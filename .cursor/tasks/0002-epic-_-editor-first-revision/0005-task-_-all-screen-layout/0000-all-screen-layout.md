# Единые правила всех экранов и внутренние прокрутки

## Контекст

Верхние служебные блоки и select повторяются на страницах; текущий адаптивный каркас складывает панели вертикально. Пользователь требует исправления всех экранов.

Родитель: [первый эпик правок](../0000-editor-first-revision.md). Все общие ограничения и решения родителя действуют для этой задачи.

## Цель

Каждый экран помещается в viewport, длинное содержимое прокручивается внутри панелей, выборы используют общий кастомный элемент.

## Границы

### Входит

- Инвентаризировать корень, configure, event, debugger, networks, project, circuit и образцы ui: панели, select и служебные вступления.
- Убрать часть со скриншота: eyebrow, отдельную строку Base, крупный заголовок, техническое описание revision/eval и баннер каталога. Допустимо компактное имя экрана в общей панели; справка не занимает постоянное рабочее место.
- Версия каталога, профиль, дата проверки и ограничения доступны компактным действием «О программе»/«Совместимость». Отсутствие игровых проверок не заменять заявлением о совместимости. При необходимости обновить `pages/release.js` и образец release-note.
- Каркас занимает доступную высоту/ширину окна; код, таблицы, списки и справка прокручиваются внутри. На узком экране переключать/сворачивать вторичные панели, сохраняя доступ к коду, командам и сетям; не складывать всё в длинный документ. Не задавать один жёсткий размер страницы в px.
- Все видимые select/option заменить общим кастомным выбором, включая скорость, профиль, порты и режимы там, где они существуют. Сохранить значения и обработчики. Нативный файловый диалог импорта не заменять.
- Диалоги и длинные меню доступны целиком внутренним скроллом, не расширяют body. Не обрезать важный контент одним overflow:hidden без доступной прокрутки.
- В каталоге UI документация и исходники имеют свою прокручиваемую область, образцы соответствуют новым правилам.

### Не входит

- Работы вне родительского эпика, публикация, изменения игровой семантики.
- Реализация во время составления задач.
