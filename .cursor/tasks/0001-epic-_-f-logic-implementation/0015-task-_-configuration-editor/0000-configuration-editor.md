# Редактор конфигурации

## Контекст

Будущая работа этапа эпика; приложение и тестовый контур ещё не реализованы. [Проект](../../../docs/specs/project.md), [API](../../../docs/specs/api.md), [редактор](../../../docs/specs/editor.md), [план развития](../../../docs/specs/roadmap.md).

## Цель

Пользователь задаёт объектную конфигурацию всех поддержанных устройств с контекстными подсказками и строгой диагностикой.

## Границы

### Входит

- Общая модель и проверки движка; вложенные discriminated-формы, совместимость всех условий и выходов, дерево Signal и Operation enums с профилем; отдельная конфигурационная грамматика без произвольного eval. Свободный JS только на странице событий.

### Не входит

- Неограниченное выполнение кода в основном редакторе, обязательный TypeScript, сборщик или фреймворк.
- Установка инструментов или реализация в ходе планирования.

## Требования и ограничения

- HTML, CSS, обычный JavaScript и нативные ES-модули; без обязательных TypeScript, сборщика и фреймворка. Устанавливаемые инструменты разработки и проверки запускаются через Docker задачи 0001, не через host npm.
- Движок независим от DOM и таймера, описание схемы отделено от состояния; игровую совместимость заявлять только после сверки с последней stable.

## Критерии приёмки

- [ ] Виджеты, подсказки и runtime-валидатор одинаково проверяют вложенные типы и сочетания; подсказки зависят от поля, устройства, состояния и профиля.
- [ ] Ошибка показывает поле, ожидаемый тип и причину; перед запуском повторная проверка не пропускает ошибочную схему.
- [ ] Конфигурация преобразуется в общую модель без исполнения произвольной логики.
- [ ] Случаи [матрицы](./media/test-matrix.md) проверены либо ограничение и причина зафиксированы; результаты реальных прогонов записаны.
