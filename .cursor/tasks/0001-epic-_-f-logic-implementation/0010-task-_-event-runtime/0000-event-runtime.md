# Событийный runtime в первом срезе

## Контекст

По уточнению пользователя 16.11.2026 событийный блок входит в первый срез. [Контракт](../../../docs/specs/event-combinator.md) определяет формы этой проектной модели: в Factorio такого блока нет. Runtime блока реализован; страница редактора остаётся задачей 0011.

## Цель

EventCombinator исполняет сценарии через общую транзакцию тика и предоставляет определённые выходы, сообщения и сохраняемое состояние.

## Границы

### Входит

- Наследование, синхронные init/main, начальный state и JSON-валидация, readonly tick/nextTick/входы.
- setOutput заменяет удерживаемую таблицу выбранных цветов; pulse — отдельный суммируемый слой с конечным сроком; clearOutput очищает оба вида собственных вкладов.
- Every tick, input changed, wakeAt/cancelWake, однократный запуск при совпадении причин; конец импульса без main.
- Клонированные сообщения {type,data}, неизменяемые конверты, сортировка по sender ID/sequence, доставка t+1.
- Подготовка/checkpoint/commit всех влияющих на следующий шаг данных. Реализовать xorshift32 и вывод начального состояния через FNV-1a, заданные событийным контрактом; отдельно проверить восстановление RNG.

### Не входит

- Полная логика поездов, другие игровые устройства, полный редактор конфигурации.
- Promise/async main, внешнее время как источник виртуальных тиков и гарантия отката внешних эффектов JS.

## Критерии приёмки

- [x] init всех блоков завершён до общей границы 0; входы в init недоступны, ошибка отменяет весь старт.
- [x] Hold A=2 плюс pulse A=3 длительностью 2 на 0→1 дают границы 2/5/5/2; цвета и чужие вклады независимы.
- [x] Сообщение шага 0→1 читается на 1 и влияет на выход на 2, порядок массива блоков не влияет.
- [x] Один main при совпадении wake/изменений/сообщений; импульс завершается даже у спящего блока.
- [x] Ошибка восстанавливает тик, сети, state, RNG, выходы, очереди и расписания без частичного commit.

## Результаты проверки

18.11.2026. `EventCombinator` исполняется через общую транзакцию `prepare/commit`. Встроенный исполнитель вызывает синхронные `init`/`main`; `createWorkerExecutor` гоняет тот же контракт в Worker. Удержание, импульс и очистка применяются в порядке вызовов и публикуются вместе с `state`, RNG xorshift32, сообщениями и пробуждениями. `reset` встроенного и Worker-исполнителя заново вызывает `init`. `capture`/`restore` продолжают прогон без `init`.

Связь сценариев — уже существующий `circuit.setPeers(event, {receiver})`. Произвольные внешние эффекты JS не откатываются. Страница редактора остаётся задаче 0011; здесь проверен протокол Worker и остановка зависшего `main`.

ER-01…ER-24 — ожидания проектной модели, не прогон Factorio. Трасса 2/5/5/2, сообщения 0→1→2, один `main` на совпавшие причины и откат checkpoint подтверждены тестами.

- `./dev/f-logic test:full` — exit 0, 142/142, включая headless Chromium. Браузерная страница прошла `2,5,5,2|async-main|timeout:0:alive`.

Покрытие c8: все файлы `src/` — 100% statements, branches, functions и lines. Общий отчёт 99.9% из-за `dev/sample/unexecuted.js`. Ветви ядра и событийного блока ради процента не исключались.
