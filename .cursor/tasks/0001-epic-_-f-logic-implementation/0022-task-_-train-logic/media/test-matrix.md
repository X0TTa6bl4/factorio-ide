# Матрица упрощённой логики поездов

Контракт — [поезда](../../../../docs/specs/factorio/trains.md). `transit` задаёт сценарий, минимум 1. Для `transit = 1` и сигнала отправления, видимого на границе 0: 0 — `at` A и `signal-T`; 1 — переход без сигнала; 2 — `at` B и `signal-T`. Конфликт двух поездов на одной станции не публикует шаг и не выбирает победителя. Очереди нет. Связь с [общей стратегией](../../media/testing-strategy.md): `test/unit/runtime/trains.test.mjs` и браузерный запуск страницы конфигурации.

| ID | Вход, шаг и действие | Ожидаемый результат | Уровень |
|---|---|---|---|
| TR-01 | Начальная пустая станция с известным station ID | Состояние присутствия и выходные сигналы соответствуют согласованной начальной таблице | контрактный |
| TR-02 | Прибытие поезда на заданном t | На каждой границе до, во время и после события состояние и сигналы соответствуют таблице из 0100 | контрактный, интеграционный |
| TR-03 | Поезд присутствует несколько шагов без новых событий | Присутствие и сигналы удерживаются или обновляются именно по контракту; повторные события не возникают самопроизвольно | интеграционный |
| TR-04 | Сигнал отправления на входе в t | Отправление и изменение сигналов на согласованных границах; чтение current не видит next | интеграционный |
| TR-05 | Маршрут A→B по стабильным station ID | Согласованные отъезд, переход и прибытие происходят в заданной последовательности и с оговорённой длительностью | интеграционный |
| TR-06 | Повтор прибытия или отправления, отсутствие поезда, неизвестный/удалённый station ID | Для каждого случая результат или диагностика явно заданы контрактом; нет скрытой потери состояния | контрактный |
| TR-07 | Несколько поездов претендуют на одну станцию или одновременно отправляются | Ожидаемый результат параметризован согласованным правилом конфликтов; все выбранные варианты проверены без придуманного приоритета | контрактный, property |
| TR-08 | Переупорядочить устройства и события с одинаковой границей | Результат соответствует согласованному порядку событий и не зависит от порядка устройств | property, интеграционный |
| TR-09 | Событийный прототип и модель получают одинаковый сценарий станций | Таблицы сигналов и состояний по тикам совпадают в согласованном подмножестве; различия описаны | интеграционный |
| TR-10 | Pause, reset, повтор с теми же входами | Пауза не меняет тик; reset и повтор дают согласованную начальную границу и идентичную последовательность | интеграционный |
| TR-11 | Сохранить и восстановить маршрут, состояние поездов, station ID и необходимые очереди | Следующий шаг и последующая последовательность совпадают с непрерывным прогоном | интеграционный |
| TR-12 | Ошибка при переходе нескольких состояний на одной границе | Атомарность и диагностика соответствуют контракту; частично опубликованные состояния отсутствуют | контрактный, интеграционный |
| TR-13 | Сравнение с заявленной игровой семантикой выбранного профиля | Фиксируются stable-версия, источник и отдельно игровые свидетельства; проектные упрощения не объявляются поведением игры | проверка соответствия игре |
