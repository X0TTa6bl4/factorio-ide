# Реализация f logic

## Библиотека интерфейса

По поручению пользователя от 17.11.2026 создана библиотека адаптивных HTML-элементов в `ui/` ([описание](../../../ui/README.md)). Исходники элементов — `ui/components/`, общие стили — `ui/styles/`; каталог и пример сборки — `ui/index.html` и `ui/workspace.html`. Задачи 0005, 0011, 0013–0018 используют её и дополняют при необходимости. Готовность дизайна не закрывает разработку движка, IDE и подключения UI к модели; статусы этих задач остаются открытыми.

## Кратко

Создать браузерный инструмент настройки и пошаговой проверки сетей Factorio на HTML, CSS и JavaScript с нативными ES-модулями. Задачи описывают будущую реализацию: создание эпика не запускает разработку, установку инструментов или публикацию.

## Контекст

В проекте есть [спецификации](../../docs/specs/README.md) и каталог игровых данных; приложения и тестового контура ещё нет. [План развития](../../docs/specs/roadmap.md) задаёт шесть этапов. Игровые правила проверяются для последней stable по [совместимости](../../docs/specs/compatibility.md); документальные ожидания и фактические сверки с игрой учитывать раздельно.

## Цель

Пользователь открывает статическое приложение по ссылке, задаёт схему объектным API классов, выполняет её по тикам, видит сигналы и использует событийные сценарии для проверки окружения. Редактор и движок используют одну модель, результат воспроизводим независимо от порядка обхода и скорости отображения.

## Границы

### Входит

- Рабочее окружение разработки и тестов, независимое ядро, четыре игровых типа комбинаторов и событийный блок.
- Пошаговый отладчик, редактор конфигурации, локальное сохранение и перенос схем.
- История и ускорение после проверки эталонного движка.
- Уточнение объёма поздних устройств, упрощённых поездов и дополнительных средств; реализация только согласованного подмножества.

### Не входит

- Реализация приложения в ходе составления этих задач.
- Обязательный TypeScript, сборщик, UI-фреймворк, прикладной сервер или аккаунты.
- Полная физика Factorio, все подключаемые устройства, автоматическая публикация, коммиты и внешние записи.
- Графический редактор проводов и обмен blueprint Factorio. Согласованный дальнейший объём — статический разбор структуры и обзор уже описанной схемы, [контракт](../../docs/specs/future-tools.md).

## Порядок выполнения и карта задач

Группы служат для предметной проработки. Порядок реализации определяется зависимостями и этапами; принадлежность одной группе не означает выполнение всех её задач подряд.

1. **Этап 1:** 0001 → 0002 → 0003 → 0004; затем базовые Constant/Arithmetic в 0005 и событийный 0010 → 0011, общая приёмка 0005 требует 0010/0011. Первой выполняется подготовка окружения, затем полная таблица сигналов — до реализации сетей и движка.
2. **Этап 2:** 0006–0009 → 0012 — полные режимы четырёх игровых комбинаторов. Событийное окружение уже поставлено первым срезом.
3. **Этап 3:** 0013 → 0014 — пригодная для проверки браузерная версия.
4. **Этап 4:** 0015 и готовая таблица 0002 → 0016 → 0017 — создание и сохранение собственных схем.
5. **Этап 5:** 0018 и 0019 могут развиваться независимо после своих входов; 0020 опирается на измерения.
6. **Этап 6:** 0021 → 0022 → 0023. Решение 0023 оставляет к реализации 0024 → 0025. Редактор холста и blueprint в этот порядок не входят.

Таблица 0002 — обязательный предшественник 0003 и 0004. Сначала закрыть её применимые конфликты имён и проверить результат, затем реализовывать токены/сети и движок. Малые тестовые наборы выбирать из готовой таблицы; отдельный выдуманный набор имён не заменяет этот вход. Номер 0002 сохраняется, порядок выполнения задают зависимости.

## Критерии приёмки

- [x] На чистой машине с Docker инструменты разработки и тестирования запускаются без установки Node.js и тестовых браузеров на хост. Прогон 2026-11-17 выполнен на текущей машине с уже установленным Docker Desktop, не на пустой виртуальной машине; команды Node на хосте не вызывали.
- [ ] Четыре игровых комбинатора и событийный блок работают через общий детерминированный шаг; выводы имеют ожидаемые значения и задержки.
- [ ] Самоссылки, циклы и несколько писателей не зависят от порядка устройств; сброс воспроизводит исходное состояние.
- [ ] Пользовательский JS можно остановить; ошибка не оставляет частично опубликованный тик.
- [ ] Сохранение и загрузка сохраняют смысл подключений и настроек; история и оптимизация сохраняют поведение эталона.
- [ ] Отчёт покрытия и карта правил подтверждают все поддержанные ветви; спорные игровые случаи имеют явный статус и эталон либо диагностику отсутствия поддержки.
- [ ] Приложение пригодно для размещения статическими файлами; публикация производится только по отдельному поручению.

## Проверка

- Сквозной сценарий: постоянный источник → арифметический → сравнивающий → выбирающий с обратной связью и событийным изменением входов; сравнить полную трассу тиков, reset и повтор.
- Сохранить схему, загрузить её, повторить сценарий; после появления истории восстановить снимок и сверить продолжение.
- Прогнать ту же схему полным и оптимизированным проходом с одним seed; сравнить сети, вклады, состояние, сообщения и расписание.
- Запустить контейнерные unit/contract/integration/browser проверки и отчёты покрытия по задачам. Контур 0001 прогнан, отчёт в его задаче. Фактических прогонов приложения пока нет: код движка ещё не реализован.

## Требования и ограничения

- Новые устанавливаемые инструменты разработки и тестов — через Docker. Docker является средством разработки; конечному пользователю достаточно браузера.
- Движок не зависит от DOM, реального времени и частоты отрисовки. Описание схемы и runtime разделены.
- Новые игровые сведения сверяются для актуальной stable перед соответствующей реализацией и выпуском.
- Открытый контракт нельзя молча заменить выбранным разработчиком поведением по умолчанию.

## Открытые вопросы
