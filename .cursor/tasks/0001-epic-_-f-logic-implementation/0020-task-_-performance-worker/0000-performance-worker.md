# Измерения производительности и решение о Worker

## Контекст

Будущая реализация опирается на [спецификацию](../../../docs/specs/factorio/ticks.md), [API](../../../docs/specs/api.md) и [план развития](../../../docs/specs/roadmap.md). Согласованную модель отличать от неподтверждённых игровых случаев.

## Цель

Есть воспроизводимые измерения больших схем и обоснованное решение о Worker с проверкой семантики, если перенос нужен.

## Границы

### Входит

- Определить нагрузки и метрики времени тика, отзывчивости и памяти, сравнить эталон и оптимизацию; при подтверждённой необходимости создать адаптер Worker без DOM и изменения модели.

### Не входит

- Публикация, коммит, произвольные дополнительные устройства и работа соседних задач. Для конечного пользователя прикладной сервер не нужен.

Нагрузки — цепь, цикл, разреженные пары, плотная шина и выбирающий `time`, размеры 1024, 4096 и 8192, `seed` 1, `historyLimit` 32.

## Проверка

- `./dev/f-logic test:full` 19.11.2026: 318/318, exit 0. Образ `f-logic-dev:1.56.1`, Node 22.20.0, Playwright 1.56.1, c8 12.0.0. `src/runtime.js` и `src/selector.js` — 100% statements, branches, functions и lines. Непокрытые строки `src/circuit.js` 280–281, 308–309, 424–425 и 428–429 — прежние отказы ID и переименования; эта задача `src/` не меняла. Профиль лежит в `test/` и в отчёт c8 не входит.
- Отдельный прогон `node --test test/unit/runtime/performance.test.mjs` в том же образе: Node `v22.20.0`, `linux/arm64`. История 32, seed 1, 2 прогрева и 5 измеренных шагов. Медианы, мс:

  | цепь, N арифметических | 8.2 / 2.0 | 12.9 / 10.2 | 23.3 / 25.1 |
  | цикл, N арифметических | 3.9 / 4.3 | 15.5 / 16.8 | 35.7 / 35.7 |
  | разреженные пары, N постоянных и N арифметических | 6.2 / 5.1 | 28.6 / 37.2 | 64.7 / 68.9 |
  | плотная шина, 1 счётчик и N сравнивающих | 5.4 / 4.5 | 16.8 / 17.4 | 37.7 / 38.2 |
  | `time`, N выбирающих | 2.8 / 3.1 | 15.1 / 15.4 | 24.6 / 22.0 |

- Худшая медиана отдельного прогона — 68.9 мс, разреженные пары 8192, `optimized`. Худший одиночный шаг того же прогона — 95.9 мс, те же пары, `full`. Следующий macrotask начинался не позже чем через 8 мс после шага. `rss` процесса доходил примерно до 864 МиБ; это чтение `process.memoryUsage()` после шагов, а не приращение одного тика. В двух `test:full` та же матрица шла рядом с другими тестами: худшая медиана 97.2 мс и 110.7 мс, оба раза разреженные пары 8192, `full`. Этот разброс — соседняя нагрузка контейнера. Решение о Worker берётся из отдельного прогона профиля.
- Headless Chromium 141.0.7390.37, разреженные пары 4096: в отдельном прогоне медианы 26.8 мс (`full`) и 17.3 мс (`optimized`), пауза до `setTimeout` 2.4 и 0.3 мс, `usedJSHeapSize` 86400000. В двух `test:full` медианы `full` / `optimized` были 38.0 / 30.3 мс и 29.9 / 23.8 мс. Конструктор `Worker` не вызывался, `document.body` доступен. Это проектные схемы, не игровой fixture.
- Решение: ядро остаётся на главном потоке. Адаптер переноса движка в Worker не создавался, поэтому PERF-4 не к чему применять. Прежний Worker событийного сценария не менялся. Матрица PERF-1…PERF-3 покрыта `test/unit/runtime/performance.test.mjs` и `test/browser/performance.test.mjs`.
