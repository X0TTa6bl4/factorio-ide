# Локальное сохранение и перенос схем

## Контекст

Будущая работа этапа эпика; приложение и тестовый контур ещё не реализованы. [Проект](../../../docs/specs/project.md), [API](../../../docs/specs/api.md), [редактор](../../../docs/specs/editor.md), [план развития](../../../docs/specs/roadmap.md).

## Цель

Пользователь сохраняет и восстанавливает определение схемы локально и через файл без потери смысла.

## Границы

### Входит

- Версионированный формат определения, стабильные ID связей вместо циклических объектов, токены сигналов и качества, профили, настройки и исходники событий; атомарная загрузка и диагностика; точка расширения для состояния сценария. Импорт не запускает пользовательский код.

### Не входит

- Снимок runtime и история/откат задачи 0017, облако, автоматическое исполнение сценария при загрузке.
- Установка инструментов или реализация в ходе планирования.

## Требования и ограничения

- HTML, CSS, обычный JavaScript и нативные ES-модули; без обязательных TypeScript, сборщика и фреймворка. Устанавливаемые инструменты разработки и проверки запускаются через Docker задачи 0001, не через host npm.
- Движок независим от DOM и таймера, описание схемы отделено от состояния; игровую совместимость заявлять только после сверки с последней stable.

## Критерии приёмки

- [ ] Экспорт и повторный импорт сохраняют ID, связи, сигналы, качество, профиль, настройки и текст сценариев; циклы представлены ID.
- [ ] Ошибочный импорт не меняет открытую схему; версия и профиль проверяются до применения, импорт сам по себе не запускает сценарий.
- [ ] Ошибки квоты и недоступного хранилища видимы и не уничтожают рабочую схему.
- [ ] Случаи [матрицы](./media/test-matrix.md) проверены либо ограничение и причина зафиксированы; результаты реальных прогонов записаны.
