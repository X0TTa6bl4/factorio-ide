# Браузерный отладчик

## Контекст

Будущая работа этапа эпика; приложение и тестовый контур ещё не реализованы. [Проект](../../../docs/specs/project.md), [API](../../../docs/specs/api.md), [редактор](../../../docs/specs/editor.md), [план развития](../../../docs/specs/roadmap.md).

## Цель

Пользователь управляет исполнением и наблюдает опубликованное состояние схемы по тикам.

## Границы

### Входит

- Запуск, пауза, скорость просмотра, одиночный шаг, сброс; тик, список устройств и подключений, сеть, собственные выходы, изменения и диагностика. Один и тот же `step()`; таймер управляет только частотой вызовов, не семантикой.

### Не входит

- Редактор конфигурации, история, графический холст, перенос движка в Worker.
- Установка инструментов или реализация в ходе планирования.

## Требования и ограничения

- HTML, CSS, обычный JavaScript и нативные ES-модули; без обязательных TypeScript, сборщика и фреймворка. Устанавливаемые инструменты разработки и проверки запускаются через Docker задачи 0001, не через host npm.
- Движок независим от DOM и таймера, описание схемы отделено от состояния; игровую совместимость заявлять только после сверки с последней stable.

## Критерии приёмки

- [ ] Ручные шаги и автозапуск до одного тика дают одинаковое состояние; пауза прекращает будущие шаги; reset возвращает начальное состояние.
- [ ] Просмотр различает агрегат сети и собственный вклад устройства, показывает изменения и ошибки без ложного продолжения.
- [ ] Случаи [матрицы](./media/test-matrix.md) проверены либо ограничение и причина зафиксированы; результаты реальных прогонов записаны.
