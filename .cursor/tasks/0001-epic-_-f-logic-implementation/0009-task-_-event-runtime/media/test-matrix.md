# Матрица событийного runtime

Это будущие проверки, а не результаты прогонов. ID связывать с реализованными тестами и правилами; измерять достижимые statements, lines, functions и branches согласно [общей стратегии](../../media/testing-strategy.md). «По контракту» означает обязательное решение шага 0100 до фиксации конкретного ожидаемого значения, а не разрешение выбрать default при реализации.

| ID | Вход, шаг и действие | Ожидаемый результат | Уровень |
|---|---|---|---|
| ER-01 | current[0]: A=1; main на 0→1 читает A и устанавливает B=2 | На 0 виден прежний выход, на 1 B=2; чтение не видит next | контрактный, интеграционный |
| ER-02 | Вычислитель читает B из ER-01 и выдаёт C=B на следующем шаге | На 1 B=2, C ещё прежний; на 2 C=2 | интеграционный |
| ER-03 | Переставить устройства ER-01/02 в массиве | Все опубликованные границы и вызовы эквивалентны | property, интеграционный |
| ER-04 | main пытается изменить tick или снимок входов | tick остаётся равным t, опубликованный вход и другие читатели не меняются; способ ошибки — по контракту | контрактный |
| ER-05 | Все порты пропущены или null | Порты отсутствуют; чтение и действия обрабатываются по контракту, вклад в сеть отсутствует | контрактный |
| ER-06 | Неверный порт, цвет, чужая сеть, недопустимый сигнал или значение | Диагностика по контракту; некорректная запись не публикуется | контрактный |
| ER-07 | set red A=1 на 0→1, без записи на 1→2 | red A=1 на 1 и 2; green и чужие вклады не изменены | контрактный, интеграционный |
| ER-08 | Set green B=2 и затем clear red на 2→3 | На 3 собственный red очищен; green B=2 и вклады иных источников остаются | контрактный, интеграционный |
| ER-09 | Set both A=1; red и green подключены к отдельным сетям | На 1 вклад A=1 в каждой; сети не сливаются; последующее изменение одного цвета не меняет другой | интеграционный |
| ER-10 | Пустой набор, clear уже пустого выхода и неподключённый выбранный выход | Сетевой вклад отсутствует; поведение пустого набора и диагностика — по контракту | контрактный |
| ER-11 | Pulse длительности 1 и N; запись на 0→1 | Проверить точные начало и конец на каждой границе по решению 0100, включая границы до и после; без скрытой общей очистки | контрактный, интеграционный |
| ER-12 | Pulse пересекает hold, другой pulse либо set/clear того же канала за шаг | Таблица приоритетов и итог каждого цвета определяются решением 0100; все порядки и окончания импульсов проверены | контрактный, property |
| ER-13 | Default every tick, входы неизменны на 0→1, 1→2, 2→3 | Ровно один main на каждом шаге | контрактный |
| ER-14 | Changed: оба входа изменились на одной границе; затем не меняются | Не более одного вызова на следующем шаге; при отсутствии изменения нового вызова нет | контрактный, интеграционный |
| ER-15 | Scheduled wake и изменение обоих входов совпадают | Один вызов за шаг; потребление и повторное назначение wake по решению 0100 | контрактный |
| ER-16 | Назначить wake на будущую границу, сохранить и восстановить снимок | Вызов происходит на согласованной границе ровно один раз; результат повтора идентичен | интеграционный |
| ER-17 | Отправить сообщение на 0→1; получатель запускается на 1→2 | Сообщение доступно на границе 1, его эффект в выходе виден на 2, не на 1 | контрактный, интеграционный |
| ER-18 | Несколько отправителей и сообщений, перестановки устройств | Порядок сообщений соответствует решению 0100 и воспроизводим; порядок массива не меняет результат | property, интеграционный |
| ER-19 | Неизвестный получатель, неверное сообщение или попытка прямого изменения чужого состояния | Диагностика/допустимость по контракту; нет скрытой частичной публикации | контрактный |
| ER-20 | Два связанных сценария станции: прибытие, присутствие и отправление | Задать таблицу входов и ожидаемых сигналов на каждой границе; обратная связь не вызывает рекурсию | интеграционный |
| ER-21 | Exception во время одного из нескольких main | Тик, сети, выходы, state, RNG, сообщения и wake остаются на последней опубликованной границе; пауза и диагностика блока/тика по контракту | интеграционный |
| ER-22 | Timeout или отклонённый async ответ | Та же атомарность ER-21; поздний ответ не публикует результат после отмены | интеграционный, браузерный |
| ER-23 | Pause, reset и повтор идентичного сценария | Пауза не продвигает тик; reset создаёт согласованную границу 0; повтор воспроизводит все границы | интеграционный |
| ER-24 | Снимок state, RNG, выходов, сообщений и wake; шаг, восстановление, повтор | Совпадают опубликованные состояния, сообщения и последующие вызовы; непредставимое состояние диагностируется по контракту | контрактный, property, интеграционный |
| ER-25 | Несколько событийных блоков и источников инициализируются до t=0 | Результат t=0 не зависит от порядка и не читает частично подготовленные сети; точный механизм и начальный вклад — по контракту | интеграционный |
| ER-26 | Повтор сценария с управляемым RNG, seed и расписанием; отдельно попытки использовать Date/Math.random/внешний ответ | Управляемый сценарий повторяет трассу; доступность внешних источников и статус воспроизводимости определяются контрактом 0100. Не обещать детерминизм произвольного JS без ограничений | контрактный, интеграционный |

Для ER-14/15 дедупликация причин запуска — предлагаемый инвариант планировщика: закрепить его в контрактном шаге до превращения строки в обязательный тест. Атомарность ER-21/22 относится к состоянию симуляции; возможность и обратимость внешних эффектов свободного JS требуют отдельного решения и не обеспечиваются Worker автоматически.
