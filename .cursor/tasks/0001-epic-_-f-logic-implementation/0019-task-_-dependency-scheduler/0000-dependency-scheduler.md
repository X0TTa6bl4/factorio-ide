# Пересчёт по зависимостям

## Контекст

Будущая реализация опирается на [спецификацию](../../../docs/specs/factorio/ticks.md), [API](../../../docs/specs/api.md) и [план развития](../../../docs/specs/roadmap.md). Согласованную модель отличать от неподтверждённых игровых случаев.

## Цель

Оптимизированный проход совпадает с полным на каждой границе и пропускает ненужные вычисления.

## Границы

### Входит

- Индекс читателей, первая очередь всех устройств, сохранение собственных вкладов, планирование по фактическому изменению сети и пробуждения устройств с состоянием.

### Не входит

- Публикация, коммит, произвольные дополнительные устройства и работа соседних задач. Для конечного пользователя прикладной сервер не нужен.

## Проверка

- `./dev/f-logic test:full` 19.11.2026: 312/312, exit 0. Образ `f-logic-dev:1.56.1`, Node 22.20.0, Playwright 1.56.1, c8 12.0.0. `src/runtime.js` и `src/selector.js` — 100% statements, branches, functions и lines. Непокрытые строки `src/circuit.js` 280–281, 308–309, 424–425 и 428–429 — прежние отказы ID и переименования; планировщик их не менял. Матрица SCH-1…SCH-11 покрыта `test/unit/runtime/scheduler.test.mjs`.
- `createSimulation({ scheduler: "full" | "optimized" })`. По умолчанию `full`: он по-прежнему вызывает каждое вычисляемое устройство на каждом шаге и отдаёт исполнителю всех участников, поэтому запрос Worker не теряет сценарии. `optimized` строит индекс читателей, на первом шаге считает все вычисляемые устройства, дальше пропускает тех, чьи входные сети не изменились, и сохраняет их последний вклад. `time` и `random` остаются в очереди каждый шаг. Сравнение сетей идёт по ключам каналов и int32; взаимно сократившиеся вклады читателя не будят.
- Очередь в снимок не входит. После `restore`, `back`, `recall` и `reset` следующий оптимизированный шаг снова считает все вычисляемые устройства, затем очередь строится по различию сетей. SCH-10 сверяет снимки, включая самоссылку, RNG, сообщения и пробуждения.
- Скрытое состояние обычного `compute` без входа, `random` и `time` оптимизированный проход не считает расписанием. Это проектная модель задержки из [тиков](../../../docs/specs/factorio/ticks.md), не игровой fixture. Мутации задержки, потери вклада и сравнения только размера или только факта записи ловятся SCH-5, SCH-1, SCH-3 и SCH-11; уцелевшей мутации этих трёх классов нет. Лишний пересчёт с тем же выходом виден по счётчику вызовов, а не по снимку.
