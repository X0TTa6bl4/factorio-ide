# Решение об инструментах будущих этапов

## Контекст

Будущая работа этапа эпика; приложение и тестовый контур ещё не реализованы. [Проект](../../../docs/specs/project.md), [API](../../../docs/specs/api.md), [редактор](../../../docs/specs/editor.md), [план развития](../../../docs/specs/roadmap.md).

## Цель

Принято и документировано решение о целесообразности и границах дополнительных инструментов.

## Границы

### Входит

- Исследовать реальные сценарии визуальных проводов, импорта/экспорта blueprint и анализа; определить матрицу поддерживаемых случаев, совместимость, риски и приоритет; после решения сформировать конкретные последующие задачи только для принятого объёма.

### Не входит

- Автоматическая реализация всех инструментов, изменение игрового ядра и публикация.
- Установка инструментов или реализация в ходе планирования.

## Требования и ограничения

- HTML, CSS, обычный JavaScript и нативные ES-модули; без обязательных TypeScript, сборщика и фреймворка. Устанавливаемые инструменты разработки и проверки запускаются через Docker задачи 0001, не через host npm.
- Движок независим от DOM и таймера, описание схемы отделено от состояния; игровую совместимость заявлять только после сверки с последней stable.

## Управление выполнением

- `work-orchestrator-ru`; `task-sdd-handoff-ru` при уточнении спецификаций.

## Skills реализации

## Skills проверки

- Дополнительный обязательный skill не требуется.

## Политика тестирования

- Писать тесты: нет для исследовательского решения; критерии будущих проверок зафиксировать в задачах.
- Запускать тесты: проверить документ и ссылки; для движка и комбинаторов действует [стратегия максимального покрытия](../media/testing-strategy.md).

- Текст MR: нет.

- [ ] Для каждого инструмента зафиксированы сценарии, альтернативы, решение и причины; матрица отделяет поддержанное, неподдержанное и требующее исследования.
- [ ] Принятый объём имеет измеримые критерии и зависимости в отдельных задачах; отклонённый не выдаётся за обязательство реализации.
