# Матрица проверок

A/B/C — разные обычные каналы; R/G — красный/зелёный вход. t+1 — следующая граница при подключённом выходе. Числовые ожидания ниже — модель спецификации, не результаты запуска игры. [Правила](../../../../docs/specs/factorio/selector.md), [метасигналы](../../../../docs/specs/factorio/meta-signals.md), [совместимость](../../../../docs/specs/compatibility.md).

| Режим | Вход и настройка | Ожидание |
|---|---|---|
| select | A=10,B=-2; убывание, индекс 0 | A=10; индекс вне диапазона при нескольких сигналах — пусто |
| select | единственный A=10, индекс вне диапазона | A=10 по документации |
| count | A=100,B=-2 → C | C=2 на t+1 |
| random | одинаковые входы, seed и последовательность тиков | одинаковая последовательность в модели; не утверждать совпадение с игрой |
| stack-size | предмет с размером стака S из каталога, вход A=2 | A=S; жидкость и виртуальный сигнал не превращаются в предмет |
| rocket-capacity | предмет с вместимостью K из каталога | A=K; не подставлять выдуманное значение |
| quality-filter | вход предметов разных качеств и заданное сравнение | остаются удовлетворяющие фильтру |
| quality-transfer | разные входные ключи переходят в один выходной ключ | вклады объединяются по правилам сети |
| quality-select | один предмет normal и rare, выбор максимума | остаётся rare; для минимума normal |
| time | контекст мира с заданным временем и длиной суток | три настроенных канала из контекста, не системных часов; фазу подтвердить |

Параметризовать пустой вход, один/несколько, отрицательные и одинаковые значения, направления, индексы и сравнения диапазонов, все качества и профили, недоступные данные и неправильные параметры. Для равенств порядка, first random, границ интервала и исчезновения выбранного сигнала, переноса качества, time и переполнения получить игровые fixtures с точными настройками, t и наблюдаемыми выходами; не выдумывать результаты. Проверить восстановление RNG и seed, изменения входа каждый тик и задержку каждого режима.

Непроверенные игровые ветви допускаются к поддержке только после fixture и обновления спецификации; до этого требуется явная диагностика неподдерживаемого случая. Проверять атомарность ошибки после принятия общего контракта ошибок.

Для каждого из девяти режимов проверить пустой вход и изменение входа между тиками; параметры и неподходящие профили должны диагностироваться. Для select проверить возрастание и убывание, все согласованные сравнения индекса и один сигнал вне диапазона. Для count вход пустой — количество 0, нормализация не создаёт ненулевой канал. Для random проверить первый выбор, границу интервала, исчезновение сигнала и повтор после восстановления состояния; конкретные игровые ожидания этих переходов требуют fixture. Для time использовать два разных контекста мира и проверять все три канала; точная фаза требует fixture.
