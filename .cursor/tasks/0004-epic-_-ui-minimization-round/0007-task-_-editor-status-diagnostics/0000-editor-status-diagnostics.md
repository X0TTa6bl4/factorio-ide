# Компактная диагностика в статусе редактора

## Контекст

Замечания 1 (удаление UI), 8 [эпика 0004](../0000-ui-minimization-round.md). Исходные формулировки сохранены в [media](../media/README.md); решения, аудит библиотеки и матрица проверки — в [проекте UI](../media/ui/design.md).

## Цель

Статус содержит результат проверки, подсказка о хоткеях доступна в руководстве.

## Границы

### Входит

- В `pages/configure/page.js`, связанных компонентах и обоих HTML-адресах редактора разместить краткий результат проверки в `.fl-editor__status`; убрать `#document-hint` только после переноса Tab/Enter/форматирования в 0001.
- Определить состояния: «Изменено · требуется проверка», «Проверка…», «Код проверен», «Строка N: причина. Исправление», ошибка симуляции и остановка. Тексты конкретные, без стека, внутренних revision/id и длинной справки.
- Использовать единый набор диагностик с запуском, подчёркиваниями и полным списком, без повторной валидации в UI. Статус — краткая сводка, подробности раскрываются по действию, не отдельный постоянный блок.
- Для диапазона оставить «К месту», для нескольких ошибок — счётчик и доступ к полному списку; не выдумывать строку для runtime-ошибки без диапазона.
- Связать сообщения с текущей revision; устаревшую ошибку не показывать как актуальную после ввода/импорта. aria-live polite, без объявления на каждый вводимый символ и без захвата фокуса.

### Не входит

- Смена стека, игровая семантика, новый API движка, коммит и публикация.
- Реализация соседних задач; подготовка этой задачи сама по себе не запускает интеграцию.
