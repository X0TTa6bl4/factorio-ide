# Компактный экран событийного комбинатора

## Контекст

Замечания 10; применение 3–5, 9, 14 [эпика 0004](../0000-ui-minimization-round.md). Исходные формулировки сохранены в [media](../media/README.md); решения, аудит библиотеки и матрица проверки — в [проекте UI](../media/ui/design.md).

## Цель

На телефоне код доступен без постоянных служебных полос, настройки/сети/сообщения открываются из рабочей области.

## Границы

### Входит

- Перестроить `pages/event/index.html` и `page.js` по панели событий `compact-workbench.html`: код — основная область, «Настройки и подключения» и «Состояние, сообщения и снимок» — раскрываемые секции, сети отдельной колонкой на широком окне и доступной панелью на телефоне.
- Вынести выбор представления в заголовок панели. Сохранить реальные настройки every-tick/input-changed, state-json, timeout-ms, сведения входов/выходов, диагностику и снимок. Скрытые настройки не теряют значение.
- Уплотнить тулбар: проверка остаётся явно названной операцией подготовки, шаг/сброс иконками; остановку Worker не подменять паузой симуляции. Не добавлять play/скорость/шаг назад, если их не поддерживает текущая сессия.
- `ui-ping`, run-meta, ui-alive и технические сведения стенда перенести из постоянных полос в раскрываемые подробности; сохранить нужную проверку отклика. Диагностика — компактная сводка у редактора, полная причина доступна.
- Сохранить session/Worker lifecycle, timeout, stop, снимок границы и возврат к обычному редактору с черновиком. Новая навигация не должна создавать обещание единой runtime-модели между экранами.

### Не входит

- Смена стека, игровая семантика, новый API движка, коммит и публикация.
- Реализация соседних задач; подготовка этой задачи сама по себе не запускает интеграцию.
