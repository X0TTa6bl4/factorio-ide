# Компактное форматирование объектов и перенос элементов массивов

## Контекст

Замечание №13 от 22.11.2026 после задачи [0005](../0005-task-_-format-and-indent/0000-format-and-indent.md): желаемый стиль задан [примером пользователя](../media/editor/formatting-example.md). Сейчас `printObject` и `printArray` в `src/config-format.js` разворачивают все непустые значения. Пользователь разрешает компактную запись одного элемента и требует каждый элемент массива с более чем одним элементом писать с новой строки.

## Цель

Форматтер воспроизводит компактный стиль примера для вложенных объектов и одиночных массивов, а массивы с двумя и более элементами оформляет с отдельной строкой для каждого элемента.

## Границы

### Входит

- В `src/config-format.js` развести оформление объекта комбинатора и вложенных значений. Верхний объект `Constant({...})`/`Decider({...})` — по одному полю на строку; между декларациями одна пустая строка. Небольшие плоские вложенные объекты без комментариев (`{ signal: ..., constant: 1 }`, `{ constant: 59 }`, `{ red: true, green: false, signal: ... }`) печатать компактно с пробелами внутри скобок и после запятых/двоеточий. Объект условия с вложенными операндами — многострочно, как в примере.
- Пустой массив без комментариев — `[]`. Один элемент — без отдельного переноса сразу после `[` и перед `]`: `signals: [{ signal: ..., constant: 1 }]`; если сам элемент сложный, допустима форма `conditions: [{` с многострочными полями и закрытием `}]` на одной строке. Не превращать одиночный сложный объект в одну длинную строку.
- При двух и более элементах печатать `[` после имени поля, затем каждый элемент с новой строки и одним дополнительным уровнем отступа; `]` — на отдельной строке на уровне поля. Правило действует рекурсивно, а не только для `signals`. Порядок элементов сохранять. Между элементами — запятые, без завершающей запятой у последнего элемента/поля, как в примере.
- Сохранить принятые U+0009 и `tab-size: 2`, общий порядок полей `src/config-schema.js`, значения, строки, комментарии и смысл программы. При комментариях разворачивать нужный контейнер, если компактная запись скрыла бы код за `//`; комментарии не терять и не переносить к другому элементу. Не исправлять идентификаторы и значения автоматически: `SSignal` остаётся опечаткой, диагностируемой задачей 0008.
- Сохранить идемпотентность, сопоставление позиции каретки, прокрутку и одну транзакцию истории при форматировании в `src/config-editor.js` / `pages/configure/page.js`; ошибочный синтаксис не переписывать. Дополнить `ui/components/code-editor.html` образцами одного и нескольких элементов; синхронизировать документацию форматирования.

### Не входит

- Изменение игровой семантики и стека; реализация кода в рамках создания этой задачи.
