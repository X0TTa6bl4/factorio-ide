# Библиотека элементов второго раунда

## Контекст

Замечания №1, 5, 6, 8–10 из [редактора](../media/editor/notes.md) и [UI](../media/ui/notes.md). Пользователь требует проектировать новые элементы и включать их в библиотеку. Расположение, состояния и размеры заданы в [проекте интерфейса](../media/ui/design.md).

## Цель

Новые элементы и состояния доступны в общей библиотеке до подключения к рабочим страницам.

## Границы

### Входит

- Создать `ui/components/editor-inspector.html`: «Сети», затем сворачиваемые «Устройства», «Формы», «Диагностика». Прокрутки и адаптивность — по проекту интерфейса.
- Создать `ui/components/tooltip.html`: действие и хоткей, hover/focus, Escape, размещение внутри окна, disabled-образец, ARIA-связь с кнопкой. Оформление — из существующих токенов.
- В `ui/components/buttons.html` добавить зеркальные SVG отмены/повтора, `.fl-button--icon`, доступные имена и tooltip.
- В `ui/components/suggest.html` показать операции со знаками, дочерние сегменты Signal, параметры пустого объекта и значения пустого поля. В `code-editor.html` показать каркас многострочного объекта и правила Enter/Tab.
- В `network-picker.html` убрать предложение «Создать <имя>» и прежнее правило «Новая сеть — первой». Служебный пункт виден только при совпадении с введённым префиксом; точное совпадение существующей сети выше остальных. Описать завершение имени по Esc/клику/Tab.
- Зарегистрировать фрагменты в `ui/index.html` и при необходимости `ui/scripts/catalog.js`. В `ui/workspace.html` собрать инспектор справа от кода из канонических фрагментов.
- Общие стили — `ui/styles/components.css` и `ui/styles/layout.css`, поведение tooltip — `ui/scripts/widgets.js`; описание элементов — `ui/README.md`.

### Не входит

- Подключение модели на рабочих страницах, игровая семантика, публикация; реализация при составлении этой задачи.
