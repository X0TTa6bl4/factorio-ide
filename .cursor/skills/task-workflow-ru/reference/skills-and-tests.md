# Скиллы и проверки

В корневой задаче фиксируй:

- «Управление выполнением»: `work-orchestrator-ru`, при необходимости `task-sdd-handoff-ru`.
- «Skills реализации»: только действительно нужные workflow из карты `repo-orientation-ru/skills.md`.
- «Skills проверки»: релевантные workflow; сами команды тестов, линтера и сборки выбирай по конфигурации проекта.
- «Политика тестирования»: нужно ли писать и запускать тесты. Явные предпочтения пользователя сохраняй; без них выбирай проверку по риску изменения.
- «Спеки и текст MR»: требуются ли спецификация и черновик PR/MR. Не добавляй их к каждой задаче автоматически.

Для движка симуляции нужны поведенческие тесты семантики тика; для простой правки документации достаточно структуры и ссылок. Не требуй PHPStan, PHPUnit или Docker в JS-проекте.

В шагах перечисляй лишь нужную часть скиллов. Не заставляй пользователя подтверждать каждый технический выбор. Отчёт всегда различает написанные тесты, реальные прогоны и проверки, которые не запускались.
