# Жизненный цикл

`draft` → `planned` → `in-progress` / `blocked` → `done` / `cancelled`.

- При создании опиши контекст, проверяемую цель, границы, критерии приёмки и проверки.
- Размещай работу внутри эпика, если она обслуживает его цель; иначе создай самостоятельную задачу. Не спрашивай размещение при очевидном соответствии.
- Разбивай на несколько шагов только по самостоятельным результатам или зависимостям, не по каждому файлу.
- `planned`: понятны реализация и приёмка, критических вопросов нет.
- `blocked`: укажи отсутствующий обязательный вход и условие разблокировки. Отсутствие необязательного Docker или Jira не является блокером.
- При выполнении обновляй галочки и фактическую проверку. Не подменяй журналом исходную цель.
- `done`: достигнут результат, обязательные проверки и явно заказанные спецификации / PR-черновики закончены.
- Обновляй `updated` фактической датой. Архивирование не следует автоматически из `done`.
