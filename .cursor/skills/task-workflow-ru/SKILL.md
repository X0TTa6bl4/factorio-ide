# Задачи проекта

Используй формат исходного workspace: директория задачи, корневой `0000`, шаги `NN00`, fix-up `NNnn`, артефакты в `media/`. Не копируй реальные задачи другого проекта.

| Работа | Читать |
|---|---|
| Создать / разместить задачу | [reference/naming.md](reference/naming.md), [reference/lifecycle.md](reference/lifecycle.md) |
| Выбрать проверки и скиллы | [reference/skills-and-tests.md](reference/skills-and-tests.md) |
| Учесть ревью и fix-up | [reference/fix-up.md](reference/fix-up.md) |
| Проверить готовность | [reference/quality.md](reference/quality.md) |

Перед созданием прочитай `.cursor/tasks/README.md` и соответствующий шаблон из `templates/`: `epic.md`, `task.md`, `bug.md`, `subtask.md` или `fix-up.md`.

Jira необязательна; без номера используй `_`. Не требуй от пользователя выбора скиллов и технических средств, которые можно обоснованно определить самому. Если цель или критерий приёмки существенно неоднозначны, уточни их.

Задача не обязывает создавать отдельные чаты или запускать субагентов. Само описание задачи не поручает реализацию; если пользователь поручил оба действия, выполни их в согласованной последовательности.

Архивируй и меняй принятую структуру только по соответствующему запросу. Статус `done` требует проверенного результата и выполнения требуемой документации, а не только закрытых галочек.
