# Границы модулей

Сохрани полезный принцип исходного скилла: внешние адаптеры зависят от прикладных сценариев и модели; чистая модель не зависит от DOM, файлов, сети или фреймворка.

Для текущего симулятора естественны отдельные части: модель схемы, движок выполнения, язык, хранение и UI. Их реальные имена определяются при реализации. Не создавай заранее пустые слои, репозитории и фабрики.

Прочитай [LAYERS.md](LAYERS.md) при выборе границы; [SERVICE_FLOW.md](SERVICE_FLOW.md) при изменении последовательности выполнения; [EXAMPLES.md](EXAMPLES.md) при обсуждении структуры файлов.

- Движок принимает данные и возвращает состояние; не читает DOM и не скачивает ресурсы.
- Описание устройства и его runtime-состояние различаются.
- UI вызывает команды движка и отображает опубликованное состояние.
- Язык создаёт ту же модель схемы, что и визуальный редактор.
- Сериализация хранит стабильные ID, а не ссылки на DOM или живые объекты браузера.
- Новая абстракция нужна только если у неё есть реальная ответственность.

Результат: понятны владелец состояния и направление зависимостей; изменение не добавляет ненужных слоёв.
