# Выполнение работы

1. Установи, поручена ли реализация или только обсуждение / планирование. Не создавай приложение из запроса на выбор стека.
2. Для задачи прочитай её `0000` и незакрытые шаги; для эпика — карту и порядок зависимостей. Для обычного поручения в чате достаточно короткого плана; не создавай дерево задач без необходимости.
3. Выполняй шаги до проверяемого результата, учитывая уже принятые решения и пользовательские изменения.
4. Выбирай команды из проекта. Отсутствие PHP, Docker, Jira или специальной модели не останавливает браузерную разработку.
5. Делегирование допустимо только когда оно разрешено пользователем или применимыми инструкциями. Само применение этого скилла не даёт разрешения на субагентов. Без него выполняй работу в текущем чате.
6. После изменений выполни необходимые проверки, запиши результаты и обнови статусы.
7. Если поручены спецификации или PR/MR-текст, примени `task-sdd-handoff-ru`; для Git-операции — `git-commit-ru`.

Не требуй перехода в другой чат для завершения уже порученной работы. Не останавливайся после первого шага, если поручена вся задача. При настоящем блокере сообщи конкретный недостающий вход и продолжи независимую часть работы.

Готово: достигнута цель, выполнены необходимые проверки и документы, пользователю сообщён результат и существенные ограничения.
