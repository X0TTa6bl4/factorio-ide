# Pull / merge

Проверь состояние дерева и upstream. Синхронизируй только целевой репозиторий и в пределах порученной операции. Для обычного обновления используй `git pull --ff-only`, если проект не требует другой стратегии; для явного объединения — `git merge <branch>`.

При конфликте читай обе стороны и сохраняй назначение обеих изменений. Разрешай очевидные технические конфликты в рамках задачи; уточняй несовместимые продуктовые решения. Не выбирай сторону целиком и не переписывай историю без основания. После разрешения выполни затронутые проверки.
