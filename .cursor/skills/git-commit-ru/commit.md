# Коммит

1. Проверь `git status --short`, текущую ветку и diff. Отдельно посмотри staged diff: там могут быть чужие изменения.
2. Выполни необходимые проверки по задаче. Для изменений только в документации достаточно проверки ссылок и структуры.
3. Формат сообщения возьми из истории и правил проекта; если истории нет, используй краткий `type(scope): описание` по-русски. Jira необязательна. Не упоминай агента и не добавляй AI-трейлеры.
4. Если запрошен только черновик сообщения, покажи его и остановись. Если коммит уже поручен, добавь конкретные файлы задачи и выполни коммит. Чужие staged-файлы не включай без необходимости.
5. Для многострочного сообщения используй временный файл и `git commit -F <file>`; не интерполируй пользовательский текст в shell.
6. Проверь итоговый commit и остаток изменений. Не исправляй уже созданную историю через `reset` или `commit-tree` автоматически.

Сообщи хеш и результат проверок. Push — отдельное действие.
