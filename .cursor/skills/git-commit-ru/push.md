# Push

Публикуй только когда пользователь поручил push. Проверь remote, текущую ветку и назначение upstream. Не выводи credentials из remote URL.

Если назначение — одноимённая ветка `origin`, первый push: `git push -u origin HEAD`. Если настроен другой remote или имя удалённой ветки, используй согласованное назначение. Не перенаправляй feature-ветку в основную. Не меняй upstream молча ради исправления предполагаемой ошибки.

Проверь результат и сообщи опубликованную ветку. Force push и прямое изменение защищённой ветки требуют явного поручения на такое действие.
