# Исправление CI

1. Зафиксируй команду, ожидаемое поведение и фактическую ошибку из предоставленных логов или локального прогона.
2. Найди тест и производственный код, который он проверяет. Если нужно, исправляй оба в пределах причины сбоя.
3. Сначала устрани причину. Не отключай тест и не ослабляй проверку ради зелёного результата.
4. Запусти соответствующий тест или проверку через существующие команды проекта. Docker нужен только если его требует само окружение проекта.
5. Если изменение затронуло общее поведение, выполни затронутые проверки; не запускай всю матрицу без причины.
6. Отделяй дефект кода от отсутствующей зависимости, недоступного сервиса и ошибки настройки. Не скрывай окружение за изменением логики.

Для движка проверяй наблюдаемую семантику: чтение одного буфера, суммирование вкладов и независимость результата от порядка устройств. Не выдавай предположения о Factorio за проверенные правила игры.

В результате укажи причину, исправление, реально выполненную команду и исход. Незапущенные проверки назови явно. Этот скилл не создаёт коммит и не меняет удалённые pipeline самостоятельно.
