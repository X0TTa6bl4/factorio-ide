# Проверка окружения

Запусти один раз перед изменением кода:

```bash
bash .cursor/skills/workspace-preflight-ru/scripts/preflight.sh
```

Скрипт определяет workspace относительно собственного расположения. Он показывает Git-корень, ветку, число изменённых файлов и наличие манифестов. Не читает `.env`, не обращается к сети, не запускает сервисы.

- `git=not-initialized` допустимо для нового проекта. Не создавай репозиторий без задачи на это.
- `dirty` — повод сохранить чужие изменения и ограничить diff, а не останавливать любую работу.
- Нужна определённая ветка — проверь её; не переключайся с потерей изменений.
- Node/npm и другие инструменты проверяй лишь для команды, которую действительно нужно выполнить. Отсутствие Docker не блокирует HTML/JS-разработку.
- Повторяй проверку при смене контекста, а не на каждом шаге.

Для короткого списка изменений одного репозитория:

```bash
bash .cursor/skills/workspace-preflight-ru/scripts/diff-stat.sh
```

Результат проверки — фактический вывод, без выдуманного статуса тестов или окружения.
