# Написание скиллов и правил

| Работа | Читать |
|---|---|
| Разделить правило и workflow | [classify.md](classify.md) |
| Создать скилл | [create.md](create.md) |
| Обновить существующий | [rewrite.md](rewrite.md) |

Сохраняй пользовательский замысел. Короткое постоянное правило относится в `AGENTS.md` / `.cursor/rules`, повторяемая условная процедура — в скилл. Поддерживай единственный набор в `.cursor/skills`; `.agents` — ссылка на `.cursor`, а не копия.

`SKILL.md` содержит YAML `name` и `description`, назначение и порядок работы. Крупные отдельные сценарии, шаблоны и скрипты вынеси в связанные файлы. Не требуй satellite у короткого самостоятельного workflow.

Для новых скиллов автоматическое обнаружение включено по умолчанию. При переносе сохраняй существующую политику вызова. Не добавляй несовместимый Cursor-флаг `disable-model-invocation` в общий `SKILL.md`; сохраняй явно выбранную пользователем политику вызова через средства соответствующего клиента.

Не вшивай отсутствующие пути, инструменты, модель агента и корпоративные ограничения как универсальные требования. Проверяй ссылки и поведение изменённых скриптов. Общесистемный `skill-creator` может применяться, если он доступен; локальный скилл не требует его установки.
