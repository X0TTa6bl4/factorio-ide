# Контракт спецификации

Опиши цель, границы, входы / выходы, инварианты, ошибки и наблюдаемые критерии приёмки. Различай требуемое, реализованное и пока открытые решения.

Для симуляции укажи представление сетей, правила чтения / записи тика, воспроизводимость и поддержанные устройства. Не объявляй особенности целевой версии игры доказанными без проверки.

Если проект использует `specs/` или `.specify`, следуй его структуре; иначе для простого документа используй `.cursor/docs/specs/<slug>.md`, если другое место не задано. Не навязывай Spec Kit ради файла.

Пути делай относительными к проекту. Не помещай в переносимую спецификацию абсолютные пути компьютера, секреты, имена чужих сервисов и внутреннюю переписку агентов. Вместо копии дневника используй итоговый контракт и проверяемые требования.
