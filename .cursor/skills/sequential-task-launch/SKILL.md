# Последовательный запуск задач

Роль управляющего чата — **шина**: очередь, зависимости, один запуск субагента на задачу, handoff при «продолжай». Реализацию, тесты и внутреннее делегирование ведёт субагент по задаче, [work-orchestrator-ru](../work-orchestrator-ru/SKILL.md) и остальным скиллам; оркестратор в это не вмешивается.

Передавай одну задачу одному субагенту и жди её завершения перед следующей.
Порядок работы — [launch.md](launch.md), готовые реплики — [prompts.ru.md](prompts.ru.md).

## Обязательные условия

1. Модель управляющего чата — **Composer 2.5** (`composer-2.5`). При другой или неподтверждённой модели не запускай очередь.
2. Модель субагента на задачу — **Grok 4.7**, точный slug `grok-4.7-high`. Не Fast, не Composer, не `inherit` и не доступная замена.
3. Первая строка задания субагенту — всегда `начинай делать NNNN`. При поручении **продолжай** (очередь после обрыва, смена субагента или следующий номер) добавляй блок передачи контекста по [launch.md § 4.1](launch.md#41-передача-контекста-продолжай); без произвольных путей вне этого блока.
4. Одновременно выполняется только один субагент этой очереди.
5. Вопрос субагента, требующий выбора пользователя, передавай без изменения; ответ возвращай тому же субагенту.
6. Управляющий агент не реализует задачи, не запускает их тесты, не коммитит и не публикует результат.

Привязки моделей сохранены по прямому указанию пользователя. Этот workflow рассчитан на среду, поддерживающую указанные модели и запуск субагентов. Установка, адаптация или обсуждение скилла не запускают очередь. Его наличие также не даёт отдельного разрешения на делегирование: требуется поручение пользователя запускать субагентов.

Задачи остаются в `.cursor/tasks/`; копии в `.agents` не создавать.
Субагенты выполняют их по [work-orchestrator-ru](../work-orchestrator-ru/SKILL.md), корневому `AGENTS.md` и применимым спецификациям. Устанавливаемые инструменты разработки и тестирования — через Docker; приложение — HTML/CSS/JavaScript с нативными ES-модулями.
