# Требования к проекту

## Библиотека элементов интерфейса

По поручению от 17.11.2026 подготовлена [библиотека](../../../ui/README.md): HTML-фрагменты в `ui/components/`, токены и общие стили в `ui/styles/`, каталог `ui/index.html`, пример сборки `ui/workspace.html`. Общие выбор, сворачиваемая панель, меню подсказок и фокус редактора живут в `ui/scripts/widgets.js`. Каталог и пример страницы показывают их состояния. Рабочие экраны подключают тот же модуль и не оставляют видимый `select`: скорость, схема, сеть, порт и режимы — этот выбор. Редактор конфигурации и страница сценария ставят меню подсказок у каретки; каталог по-прежнему только показывает образец. Нативный файловый диалог импорта не заменяется. Это не меняет модель схемы. Поведение демонстрации не реализует движок, IDE или сохранение.

## Назначение

`f logic` — лёгкий браузерный инструмент для проектирования и пошаговой проверки логических сетей Factorio вне игры. Референс — [cnide](https://github.com/charredUtensil/cnide). Конфигурация задаётся через JavaScript API классов комбинаторов; редактор и движок используют общую модель схемы, сигналы доступны для просмотра по тикам. Первоначальное предложение собственного C-подобного псевдоязыка заменено объектной конфигурацией.

## Запуск и публикация

- Исходный код публикуется на GitHub; приложение — через GitHub Pages.
- Пользователь открывает публичную ссылку в современном браузере. Скачивать репозиторий, устанавливать Node.js или запускать команды не требуется.
- Симуляция, редактирование и просмотр результата выполняются на устройстве пользователя. Для первого этапа прикладной сервер и аккаунт не нужны.
- Открытие локального `index.html` двойным кликом и полный офлайн-режим не являются обязательными требованиями.
- Данные схем хранятся в браузере и переносятся через импорт/экспорт файла по [документу схемы](project-document.md); это не облачное сохранение.

GitHub Pages обслуживает статические HTML/CSS/JS-файлы. Публикацию можно автоматизировать после изменения исходников; обязательного этапа сборки нет. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

## Согласованный стек

Решение согласовано 10 ноября 2026 года.

| Часть | Технология и назначение |
|---|---|
| Структура интерфейса | HTML |
| Оформление | CSS |
| Движок и поведение интерфейса | Обычный JavaScript |
| Организация кода | Нативные ES-модули с `import` и `export` |
| Выполнение | Браузер пользователя |
| Размещение | Статические файлы на GitHub Pages |

Начальный вариант разрабатывается без обязательного сборщика и сторонних библиотек. TypeScript, Vite и UI-фреймворк в согласованный стек не входят. Инструменты типизации JavaScript, разбора конфигурации и редактора выбираются отдельно по мере детализации этих функций.

### Окружение разработки и тестирования

Если для разработки или тестирования нужно установить инструменты, они устанавливаются и запускаются через Docker. Подготовка этого окружения — первая задача реализации. Node.js, средства покрытия и тестовые браузеры не должны требовать отдельной установки на хост; версии контейнеров и пакетов фиксируются при создании контура. При отсутствии Docker описать его установку для платформы разработчика; не устанавливать его автоматически в ходе планирования.

Тестовые зависимости допустимы внутри контура разработки и не становятся обязательными библиотеками приложения. Для движка и комбинаторов требуется максимальное покрытие поведения и достижимых ветвей по [стратегии тестирования](../../tasks/0001-epic-_-f-logic-implementation/media/testing-strategy.md). Команды и закреплённые версии — в [окружении разработки](../../../dev/README.md): образ `f-logic-dev:1.56.1` (Node 22.20.0, npm 10.9.3, `node:test`, c8 12.0.0, Playwright 1.56.1). Dev-server только раздаёт файлы и публикует порт на 127.0.0.1. Проверка библиотеки интерфейса остаётся в `ui/tests`. Эти команды не пересобирают `data/factorio`.

### Движок

- Движок — самостоятельные JavaScript-модули без зависимости от DOM, элементов интерфейса и таймера отрисовки.
- Описание схемы отделено от состояния выполнения. Объектный API и UI используют общую модель схемы.
- Один завершившийся `await step()` выполняет ровно один тик; `await reset()` восстанавливает начальное состояние. Асинхронный исполнитель нужен для пользовательского Worker; чистое вычислительное ядро остаётся независимым. Интерфейс получает опубликованное состояние для отображения.
- Ручной шаг и автоматический запуск используют один алгоритм. Частота вызовов и отрисовки определяет скорость просмотра, но не результат последовательности тиков.
- Арифметика сигналов реализуется отдельными функциями с правилами int32 из [спецификации сетей](factorio/networks.md); обычное поведение `Number` не считается достаточным для совместимости.

### Web Worker

Ядро тика выполняется в основном потоке страницы. Пользовательский JavaScript событийного блока в первом срезе выполняется в останавливаемом Worker: страница `pages/event/index.html` и контракт [событийного комбинатора](event-combinator.md). Worker не обращается к DOM. Полный перенос движка в Worker не входит в первый срез. Интерфейс показывает только опубликованную границу.

### Браузерный отладчик

Страница `pages/debugger/index.html` управляет уже созданным прогоном. Запуск, пауза, скорость просмотра, одиночный шаг и сброс вызывают одни и те же `step()` и `reset()`. Таймер выбирает паузу между вызовами и не участвует в расчёте. Контракт просмотра, ошибок и демонстрационных схем — в [отладчике](debugger.md).

## Последовательность разработки

Предлагаемый порядок, зависимости и результаты этапов собраны в [плане развития](roadmap.md). Приоритет — корректные сети и тики с минимальными Constant/Arithmetic и событийным блоком уже в первом срезе; затем полная поддержка четырёх игровых комбинаторов на втором этапе. Далее развиваются браузерный отладчик, основной редактор и сохранение; остальные игровые устройства добавляются на проверенное ядро.

История с шагом назад желательна, но не должна задерживать проверку ядра. Обзор проводов и разбор структуры описаны в [дополнительных средствах](future-tools.md). Редактор холста и обмен blueprint Factorio в объём не входят.

## Границы модели

Сети хранятся в массиве и имеют стабильные ID. Вычисляемые комбинаторы ссылаются на красную и зелёную сети входа и выхода. Постоянный источник имеет только выходную сторону. Описание схемы, runtime-состояние и UI разделяются; движок работает без DOM.

Упрощение первого этапа: вычисляемые комбинаторы считаются полностью обеспеченными электричеством; строительство, исследования и энергосистема не симулируются. Неподдержанный режим должен выдавать диагностику, а не незаметно заменяться пустым выходом.

Подробности — [сети](factorio/networks.md), [тики](factorio/ticks.md). Версия игры — [последняя стабильная](compatibility.md).

## Контракты и открытые вопросы

Формы конфигурации, типы операндов, константы и выходные ветки определены в [объектном API](api.md). Подсказки, диагностика и повторная проверка перед запуском — в [правилах редактора](editor.md). Текст редактора — декларативная запись: `Arithmetic({...})` и такие же вызовы `Constant`, `Decider`, `Selector` разбираются в те же классы. Объектный API по-прежнему создаёт комбинатор через `new Класс({...})`. Прежние декларации редактора открываются вместе с новым текстом. Файл схемы хранит устройства, ID, сети, группы и peers независимо от этой записи.

Сети автоматически создаёт редактор/движок; неподключённые порты можно пропускать. `null` означает незаданный операнд, а условие сравнивающего с таким операндом ложно. Подробные договорённости и оставшиеся вопросы собраны в [API](api.md). Основной редактор содержит конфигурацию; свободный JS тестового окружения задаётся наследником [событийного комбинатора](event-combinator.md) с переопределённым `main`, доступом к тику, сетям и другим сценариям. Его реализация включена в первый срез по уточнению 16.11.2026; служебный контракт первого среза определён в отдельном документе. Не подменять открытые решения самостоятельно выбранными значениями по умолчанию. Непроверенные игровые случаи хранятся в документах конкретных устройств.

## Критерии приёмки первого среза

- Схема с минимальными Constant/Arithmetic и EventCombinator настраивается и выполняется по шагам в браузере; полные режимы четырёх игровых типов относятся к следующему этапу.
- Видны номер тика, сигналы выбранной сети и выходы выбранного устройства.
- Порядок устройств в массиве не меняет результат; обратные связи не требуют рекурсии.
- Поддержанные режимы имеют поведенческие проверки; неподдержанные явно обозначены.
- Приложение открывается по ссылке GitHub Pages без локальной установки и работает без прикладного сервера.
- Опубликованная версия показывает, с какой стабильной версией Factorio проверена совместимость.

## Примеры и статический выпуск

Точка входа — корневой `index.html`: редактор обычных комбинаторов, запуск и сигналы сетей. Ссылки на стили, модули и страницы относительные: тот же набор открывается из корня HTTP-сервера и под префиксом `/factorio-ide/` с завершающим `/`. Прямой адрес `pages/configure/` открывает тот же редактор. Прикладного сервера и установки у пользователя нет. Локальные адреса — в [README](../../../README.md).

Демонстрации постоянного, арифметического, сравнивающего и выбирающего собраны на `pages/examples/index.html` и открываются в [отладчике](debugger.md). Событийный сценарий Arrival выполняется в Worker на `pages/event/index.html`; с редактора на него ведёт отдельная кнопка, обратный переход возвращает черновик вкладки. Макет `ui/workspace.html` собирает библиотеку и не является прогоном.

Пользовательское руководство открывается кнопкой «Документация» и лежит в `pages/docs/`. Статья «Совместимость» показывает номер снимка каталога, дату проверки stable и прямо говорит, что совместимость вычислений с игрой не заявлена. Баннер не занимает место экрана. Отсутствующий файл и неподдержанный режим дают статус HTTP или код ошибки и не подменяют его заявлением о совместимости. Страница схемы помещается в окно: таблицы и текст сценария прокручиваются внутри, импорт остаётся нативным файловым диалогом. Профиль открытой схемы виден в строке файла, а не в отдельной модалке.
