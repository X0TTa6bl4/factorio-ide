# Объектный API конфигурации

Основной документ форм объектов, типов и значений по умолчанию. API классов JavaScript заменяет первоначальное предложение собственного псевдоязыка. Реализации пока нет. Принятые правила отделены от открытых вопросов ниже.

Подсказки и диагностика описаны в [правилах редактора](editor.md), игровые вычисления — в `factorio/`. При изменении формы данных сначала обновляется этот документ, затем зависимые примеры.

## Форма записи

Комбинатор создаётся через класс с одним объектом конфигурации:

```js
const arithmetic = new Arithmetic({
    red_input: red_10,
    green_input: green_100,

    red_output: red_20,
    green_output: null,

    left_operand: {
        red: true,
        green: true,
        signal: Signal.Logistic.$WOOD_BOX
    },

    right_operand: {
        constant: 5
    },

    operation: Arithmetic.Operation.SUM,

    return: Signal.Logistic.$WOOD_BOX
});
```

Это пример требуемого API, а не исполняемый модуль. Ссылки на сети предоставляет редактор/движок автоматически. Короткие `$IRON`, `$EACH` в старых примерах обозначают сигнальные константы; актуальная форма доступа — дерево `Signal`, описанное ниже. Полный набор имён ещё предстоит сопоставить с каталогом.

В JavaScript свойства с именами передаются внутри `{}`. Запись `new Arithmetic(red_input: red_10, ...)` не допускается. Порядок свойств объекта не задаёт порядок работы устройств или операндов во времени.

## Подключения сетей

| Свойство | Допустимое значение |
|---|---|
| `red_input` | Переменная со ссылкой на объект красной сети либо `null` |
| `green_input` | Переменная со ссылкой на объект зелёной сети либо `null` |
| `red_output` | Переменная со ссылкой на объект красной сети либо `null` |
| `green_output` | Переменная со ссылкой на объект зелёной сети либо `null` |

Строки с именами сетей, числа, операции и сигнальные константы в этих полях не допускаются. Ссылки должны относиться к сети текущей схемы; цвет проверяется отдельно от факта наличия объекта.

`null` в подключении означает отсутствие провода. Все четыре свойства подключений можно пропускать: отсутствующий порт получает `null`. Неподключённый выход ничего не передаёт в сети. Это не то же самое, что незаданный операнд.

Редактор/движок создаёт сети автоматически и предоставляет переменные со ссылками на них. При заполнении подключения подсказки предлагают уже созданные сети подходящего цвета текущей схемы. Ручные объявления `new Network(...)` не требуются. Повторное использование одной переменной означает ту же сеть, а не создание копии. Конкретное действие создания новой сети, генерация имён и правила переименования ещё требуют описания интерфейса; запись неизвестного идентификатора сама по себе не согласована как команда создания.

При подключении устройство регистрируется как читатель входной сети и как источник выходной. Это служебные зависимости движка, не дополнительные пользовательские поля. Отключение или удаление устройства снимает регистрацию; повторное подключение не создаёт дублирующих подписок. Регистрация в конструкторе возможна при наличии контекста схемы; алгоритм расчёта определён в [тиках](factorio/ticks.md).

Одна сеть может одновременно подключаться ко входу и выходу соответствующего цвета. Такая обратная связь разрешена и выполняется по [правилам тиков](factorio/ticks.md). Сигнальный операнд выбирает только входы устройства; чтение выходных портов и произвольных сетевых ссылок в его полях не предусматривается.

## Общий тип операндов

У арифметического оба свойства имеют один тип:

```text
left_operand:  Operand | OperandConst | null
right_operand: Operand | OperandConst | null
```

Объединение типов не означает смешивание полей вариантов. Каждый непустой операнд должен полностью соответствовать ровно одному из двух объектов.

### Operand: чтение сигнала

```js
{
    red: true,
    green: false,
    signal: $IRON
}
```

| Поле | Требование |
|---|---|
| `red` | Обязательный `boolean` |
| `green` | Обязательный `boolean` |
| `signal` | Обязательная константа обычного сигнала либо разрешённого метасигнала |

Поле `constant` запрещено. Значения `1`, `0`, `"true"` и `"false"` не заменяют boolean. Цветовые флаги независимы для левого и правого операнда; они выбирают подключённые входы, а не задают отдельную арифметическую операцию. Оба флага `false` допустимы: выбранный набор входных сигналов пуст. Обычный канал читается как 0 и в арифметическом, и в сравнивающем; метасигналы используют правила пустого набора. Маска не равносильна незаданному операнду. Например, `A+5` при отключённых входах и выбранном выходном сигнале B даёт B=5 на следующей границе; незаданный выходной сигнал ничего не создаёт.

Общий тип объекта не разрешает все метасигналы во всех позициях. Допустимость определяется документом комбинатора; чтение входов — [моделью сетей](factorio/networks.md).

### OperandConst: числовая константа

```js
{
    constant: 5
}
```

`constant` — единственное допустимое и обязательное поле этого варианта. Значение — конечное целое число в диапазоне int32, определённом в [модели сетей](factorio/networks.md). `red`, `green` и `signal` запрещены.

Строка `"5"`, дробь, `NaN`, бесконечность и число вне диапазона отклоняются. Введённая настройка не должна молча преобразовываться в число, округляться или переполняться. Переполнение вычислений сигналов определяется отдельно в [модели сетей](factorio/networks.md).

Прямое `right_operand: 5` или `left_operand: 0` запрещено: числовой вариант всегда объект.

### null

`null` разрешён как отдельное значение обоих операндов и означает «операнд не задан». Это допустимое состояние, не числовой 0. По уточнению пользователя незаданная обработка не должна создавать выходной вклад. Для арифметического незаданный обязательный операнд оставляет выход пустым; прежний вклад после очередного шага исчезает. `{ constant: 0 }` — явно заданный числовой операнд, с которым операция выполняется.

В сравнивающем условие с `null` в любом операнде всегда ложно. Оно остаётся в выражении AND/OR: `false AND X` ложно, `false OR X` равно X. Ветка выбирается по результату всего выражения; при итоговом `false` используется `when_false`. Это правило конфигурации нашего API; `null` не подменяется игровым чтением отсутствующего канала как 0.

## Константы сигналов, операций и выход

- Сигналы доступны через дерево классов со статическими константами. Согласованный пример: `Signal.Logistic.$WOOD_BOX` для предмета `wooden-chest`. Пользователь не повторяет `{type, name, quality}`. Группа `Logistic` организует доступ, но не заменяет игровой тип сигнала `item`.
- Прежние короткие `$IRON`, `$EACH` и другие имена в примерах — обозначения сигналов, а не обязательные глобальные переменные нового API. Для метасигналов используются `Signal.Meta.$EACH`, `Signal.Meta.$EVERYTHING`, `Signal.Meta.$ANYTHING`. Группы и технические типы различаются в [каталоге](factorio/catalog.md); предложение публичного дерева приведено ниже.
- Константы сигналов и операций должны иметь различимые типы. Если свести обе группы к произвольному `number`, необходимая проверка соответствия теряется. Техническое представление констант пока не выбрано.
- `operation` принимает константу операции именно своего типа комбинатора. Пример для арифметического — `Arithmetic.Operation.SUM`. Произвольная строка `"SUM"` и операция другого устройства запрещены. Полный набор имён констант определяется отдельно по списку поддержанных операций.
- У арифметического `return` задаёт выходной сигнал либо допустимый метасигнал. Если выходной сигнал не выбран, выходной вклад пуст: вычисленное число не создаёт канал автоматически. Отдельно подключение определяет, в какие сети попадёт выбранный выход; при обоих отключённых выходных портах в сети ничего не передаётся. Число `123`, операция и ссылка на сеть не являются выходными сигналами. Настройки выхода сравнивающего имеют отдельный контракт.
- Один объект `Arithmetic` задаёт одну игровую операцию. Функции для пользовательских вычислений внутри операндов и цепочки арифметических выражений не входят в согласованный формат.

Правила `$EACH` и сбор результатов определяются [арифметическим комбинатором](factorio/arithmetic.md). Названия метасигналов и их ID — в [едином справочнике](factorio/meta-signals.md).

### Дерево Signal

Состав разделов получен из официальных данных. Пользователь принял предложенное дерево и способ выбора качества; это имена нашего API, а не классы Factorio. `Logistic` и `$WOOD_BOX` сохраняют первоначально согласованную запись.

| Раздел | Класс | ID группы |
|---|---|---|
| Логистика | `Signal.Logistic` | `logistics` |
| Производство | `Signal.Production` | `production` |
| Промежуточные продукты | `Signal.Intermediate` | `intermediate-products` |
| Космос | `Signal.Space` | `space` |
| Вооружение | `Signal.Combat` | `combat` |
| Жидкости | `Signal.Fluids` | `fluids` |
| Сигналы | `Signal.Signals` | `signals` |
| Враги | `Signal.Enemies` | `enemies` |
| Окружение | `Signal.Environment` | `environment` |
| Несортированное | `Signal.Unsorted` | `other` |

`Signal.Meta` отдельно предоставляет логические метасигналы, не являясь одиннадцатой игровой вкладкой. Пользовательская запись обычного сигнала имеет форму `Signal.<раздел>.$<имя>`; дополнительные ветви `Recipe` и `Entity` не вводятся. Для деревянного сундука используется только `Signal.Logistic.$WOOD_BOX`. Игровой тип хранится внутри определения константы.

Для обычного сигнала без указанного качества используется `normal`. Явный выбор: `Signal.Logistic.$WOOD_BOX.withQuality(Quality.RARE)` возвращает новый токен и не меняет базовую константу. `Quality.NORMAL`, `UNCOMMON`, `RARE`, `EPIC`, `LEGENDARY` обозначают модификаторы качества, а не передаваемые сигналы качества. Такие сигналы существуют отдельно среди игровых каналов. Наличие качества проверяется по профилю.

Техническое уточнение: в каталоге есть `item/wooden-chest`, `recipe/wooden-chest`, `entity/wooden-chest`. Это разные игровые идентификаторы, несмотря на совпадающую подпись. Короткая константа `Signal.Logistic.$WOOD_BOX` соответствует предметному сигналу `item/wooden-chest`; краткая форма API не означает объединение игровых каналов. Правило идентичности `type + name + quality` сохраняется. [SignalID](https://lua-api.factorio.com/latest/concepts/SignalID.html).

## Сравнивающий комбинатор

`Decider` использует массив `conditions`. Условие содержит `left_operand`, `right_operand` и операцию сравнения; со второго условия задаётся связка с предыдущим. Структурные формы операндов переиспользуются, но допустимость вариантов и метасигналов зависит от позиции. Написание `Decider.Operation` и `Decider.Logic` пока предложено; полный контракт условий ещё предстоит согласовать. Приоритет AND/OR — в [правилах сравнивающего](factorio/decider.md).

Ветки `when_true` и `when_false` находятся непосредственно в конфигурации, без обёртки `outputs` и поля `return`. Их общий тип — массив выходных настроек либо `null`. Отсутствующий параметр получает `null`; `null` и `[]` означают отсутствие настроек ветки. Это согласованное значение по умолчанию не определяет смысл `null` у операнда.

### Фиксированное количество

```js
when_true: [
    {
        signal: $COAL,
        constant: 5
    }
]
```

`signal` задаёт обычный сигнал либо допустимый метасигнал, `constant` — целое int32. Количество не ограничено единицей; при добавлении настройки редактор предлагает 1. Это отдельный выходной тип с полем `signal`, а не `OperandConst`.

### Копирование количества

```js
when_false: [
    {
        signal: $COAL,
        red: true,
        green: false
    }
]
```

`red` и `green` — boolean-флаги входных цветов копирования; `constant` запрещён. Для обычного конкретного сигнала смешивание этих флагов с фиксированным количеством запрещено. Метасигнальный фиксированный выход имеет отдельную форму ниже.

### Фиксированное количество для набора каналов

Согласованный пример: выдать каждому присутствующему сигналу выбранного красного входа количество 1 при срабатывании ветки:

```js
{
    signal: Signal.Meta.$EVERYTHING,
    constant: 1,
    red: true,
    green: false
}
```

Маска выбирает набор каналов, а `constant` — их выходное количество. Это не копирование входных количеств. Оба флага обязательны; при обоих `false` выбранный набор пуст. Аналогичные структурные настройки разрешаются только с допустимыми для данного условия метасигналами; их фильтрация определяется [справочником метасигналов](factorio/meta-signals.md). Форма объекта не отменяет ограничений `Each`/`Everything` и не объявляет сложные игровые сочетания проверенными.

Вычислительная семантика режимов и ограничения метасигналов — в [сравнивающем комбинаторе](factorio/decider.md).

## Постоянный и выбирающий

Постоянный комбинатор задаёт набор выходных сигналов и их количеств. Входных портов у него нет; есть выходные подключения красного и зелёного цветов. Требования к секциям и группам — в [спецификации постоянного](factorio/constant.md); окончательная форма его объекта ещё не согласована.

В документации используются четыре русских названия: **арифметический**, **сравнивающий** (`Decider`), **постоянный**, **выбирающий** (`Selector`). Ранее употреблявшийся «решающий» означает сравнивающий, а не выбирающий. Имена классов JavaScript этим переименованием не меняются.

## Основной редактор и сценарии

Основной редактор содержит только конфигурацию схемы: устройства, подключения, константы и настройки. Свободная исполняемая логика выносится на отдельную страницу в сценарии [событийного комбинатора](event-combinator.md). Это дополнительный инструмент тестирования, которого нет в игре; он не заменяет четыре игровых типа.

## Необязательные параметры

«Можно пропустить параметр» означает, что свойство отсутствует в объекте целиком. Согласовано: отсутствие любого подключения эквивалентно явно записанному `null`.

Для `when_true` / `when_false` отсутствие также означает `null`. Для вложенного `Operand` поля `red`, `green`, `signal` по-прежнему обязательны. Для остальных настроек автоматические значения по умолчанию не введены; например, отсутствие `operation` не становится `SUM`.

## Открытые вопросы

- Действие создания новой сети в UI, генерация/переименование переменных и восстановление их по стабильным ID. Автоматическое создание и подсказки существующих ссылок согласованы.
- Выбрать техническое представление токенов и правила генерации уникальных имён в форме `Signal.<раздел>.$<имя>`. Дополнительные ветви типов исключены; группы и явное качество согласованы выше.
- Обязательность остальных настроек и их значения по умолчанию. Подключения и выходные ветки можно пропускать; обязательные поля операндов определены выше.
- Контракты сравнивающего, постоянного и выбирающего: не переносить на них все ограничения арифметического автоматически.
- Поведение выходной настройки с пропущенным `constant` и неполной маской: игровое значение по умолчанию само по себе не выбирает вариант нашего объекта.
- Формат описания конфигурации основного редактора и способ её чтения. Разделение «конфигурация здесь, свободный JS в событийном блоке» согласовано; точный синтаксический набор конфигурационного файла ещё не описан.
- Детали служебного API событийного блока: аргументы управления собственным выходом и импульсами, начальное состояние, формат сообщений и восстановление. Режимы запуска `main` и доставка сообщений на следующей границе тика согласованы в отдельном документе.

Непроверенные случаи поведения игры хранятся в документах соответствующих комбинаторов, отдельно от вопросов формы API.
