# Объектный API конфигурации

Основной документ форм объектов, типов и значений по умолчанию. API классов JavaScript заменяет первоначальное предложение собственного псевдоязыка. Классы и чтение конфигурации без eval реализованы; открытые вопросы формы перечислены ниже.

Подсказки и диагностика описаны в [правилах редактора](editor.md), игровые вычисления — в `factorio/`. При изменении формы данных сначала обновляется этот документ, затем зависимые примеры.

## Форма записи

Комбинатор создаётся через класс с одним объектом конфигурации:

```js
const arithmetic = new Arithmetic({
    red_input: red_10,
    green_input: green_100,

    red_output: red_20,
    green_output: null,

    left_operand: {
        red: true,
        green: true,
        signal: Signal.Logistic.wooden_chest
    },

    right_operand: {
        constant: 5
    },

    operation: Arithmetic.Operation.SUM,

    return: Signal.Logistic.wooden_chest
});
```

Это пример требуемого API, а не исполняемый модуль. Ссылки на сети предоставляет редактор/движок. Публичные имена сигналов строятся из их внутренних игровых имён; полная таблица готовится отдельной задачей.

В JavaScript свойства с именами передаются внутри `{}`. Запись `new Arithmetic(red_input: red_10, ...)` не допускается. Порядок свойств объекта не задаёт порядок работы устройств или операндов во времени.

## Подключения сетей

| Свойство | Допустимое значение |
|---|---|
| `red_input` | Переменная со ссылкой на объект красной сети либо `null` |
| `green_input` | Переменная со ссылкой на объект зелёной сети либо `null` |
| `red_output` | Переменная со ссылкой на объект красной сети либо `null` |
| `green_output` | Переменная со ссылкой на объект зелёной сети либо `null` |

Строки с именами сетей, числа, операции и сигнальные константы в этих полях не допускаются. Ссылки должны относиться к сети текущей схемы; цвет проверяется отдельно от факта наличия объекта.

`null` в подключении означает отсутствие провода. Все четыре свойства подключений можно пропускать: отсутствующий порт получает `null`. Неподключённый выход ничего не передаёт в сети. Это не то же самое, что незаданный операнд.

Редактор создаёт сети через общий объект `Circuit` и предоставляет переменные со ссылками на них. Пользователь выбирает `green_new` / `red_new` либо завершает введённое имя своего цвета; служебный вариант `_new` сразу заменяется настоящим именем. Повторное использование переменной означает ту же сеть. Правила префикса, MRU, удаления неиспользуемых сетей и кеша — в [редакторе](editor.md). Строки допустимы в служебном методе получения сети ниже, но не в портах комбинатора.

Конструктор комбинатора проверяет его конфигурацию; регистрация в схеме и входных/выходных сетях выполняется через `Circuit.add`. Отключение или удаление снимает регистрацию; повторное добавление того же объекта в ту же схему идемпотентно. Один объект устройства не принадлежит двум схемам. Алгоритм расчёта — в [тиках](factorio/ticks.md).

Одна сеть может одновременно подключаться ко входу и выходу соответствующего цвета. Такая обратная связь разрешена и выполняется по [правилам тиков](factorio/ticks.md). Сигнальный операнд выбирает только входы устройства; чтение выходных портов и произвольных сетевых ссылок в его полях не предусматривается.

## Объект схемы для редактора, тестов и первой страницы

Проектный контракт первого среза от 16.11.2026: один `Circuit` владеет сетями и устройствами. Редактор, загрузчик и тесты используют одну службу, не конструируют `Network` и не собирают подписки вручную.

| Метод | Результат |
|---|---|
| `new Circuit({profile: "base"})` | Пустое описание схемы с выбранным каталогом; runtime создаётся отдельно |
| `circuit.network("green_buffer1")` | Ссылка на сеть этого имени; при отсутствии создаётся, при повторе возвращается та же сеть |
| `circuit.add(device)` | Регистрирует объект устройства и подключения, выдаёт стабильный ID, возвращает устройство |
| `circuit.setPeers(event, {receiver: otherEvent})` | Заменяет связи сценария после регистрации блоков; позволяет собрать двусторонние ссылки без forward reference в JS |
| `circuit.remove(device)` | Удаляет устройство и его регистрации в описании |
| `circuit.renameNetwork(network, "green_buffer2")` | Меняет имя, сохраняя ID; цвет менять нельзя, занятое имя вызывает ошибку |
| `circuit.networks` | Сети, которые сейчас входят в описание |
| `circuit.detachNetwork(network)` | Исключает сеть из описания и сохраняет объект с прежним ID |
| `circuit.restoreNetwork(network, name)` | Возвращает ранее исключённую сеть этой схемы; ID не выдаётся заново |
| `circuit.createSimulation()` | Возвращает Promise: атомарно проверяет описание, удаляет сети без ссылок и создаёт независимый runtime на границе 0 после init |

`network(name)` — служебный API. В пользовательском конфигурационном тексте остаются переменные `red_...` / `green_...`; редактор разрешает их через эту службу. Цвет извлекается из префикса имени, суффикс содержит буквы ASCII, цифры и подчёркивания и не пуст. Имена `red_new` и `green_new` зарезервированы для действия редактора и не являются настоящими сетями. Неизвестное имя вне порта не создаёт сущность. В готовом тексте конфигурации ссылка подходящего цвета в порте восстанавливает сеть без строки `wire` и без повторного подтверждения; пока текст ещё вводится, новое имя своего цвета создаётся завершением токена (Esc, клик или Tab), а отмена этой правки сеть не оставляет. Устаревший ответ меню текст и сети не меняет. При загрузке уже сохранённого корректного объявления сети служба восстанавливает его без повторного UI-действия.

ID не равен имени, позиции массива или числовому суффиксу. Он не переиспользуется после удаления. Заново созданная `green_2` имеет новый ID и пустое состояние; undo до удаления восстанавливает старый ID из транзакции редактора. Сети могут временно не иметь ссылок при сборке описания; очистка выполняется после полной успешной транзакции/валидации, а не между `network()` и `add()`.

Редактор может заново собрать объект устройства с тем же ID: правка поля и вставка соседнего вызова не переназначают ID. Удалённое устройство и отменённая резервация ID повторно не выдаются. В тексте конфигурации ID не записывается.

Для воспроизводимого событийного RNG Circuit принимает необязательный `seed` — uint32, по умолчанию 1. Это seed модели, не внутренний seed Factorio. Runtime не разделяет изменяемые данные с описанием или другим прогоном.

`circuit.defineNetwork(name, id)` создаёт сеть с уже известным ID или возвращает сеть этого имени. `circuit.add(device, id)` так же принимает известный ID устройства. Без ID счётчик выдаёт следующий свободный номер и не переиспользует удалённые. Эти вызовы нужны загрузчику файла; в тексте конфигурации по-прежнему остаются имена сетей.

`createSimulation({ historyLimit })` задаёт, сколько опубликованных границ хранит прогон. Без параметра предел равен 32. Значение — целое число от 1; иное даёт `invalid-simulation-options` до создания прогона. `historyTicks`, `historySnapshot`, `back` и `recall` читают и восстанавливают эти снимки. Состав, вытеснение старых границ, новая ветка и коды ошибок — в [тиках](factorio/ticks.md). Файл схемы историю не содержит.

Файл определения, локальная запись и правила импорта описаны в [документе схемы](project-document.md). Импорт не подменяет снимок runtime и не запускает текст сценария.

```js
const circuit = new Circuit({ profile: "base" });
const red_1 = circuit.network("red_1");
const green_buffer1 = circuit.network("green_buffer1");

circuit.add(new Constant({
    enabled: true,
    red_output: red_1,
    signals: [{ signal: Signal.Logistic.wooden_chest, constant: 3 }]
}));

circuit.add(new Arithmetic({
    red_input: red_1,
    green_output: green_buffer1,
    left_operand: { red: true, green: false, signal: Signal.Logistic.wooden_chest },
    right_operand: { constant: 2 },
    operation: Arithmetic.Operation.SUM,
    return: Signal.Logistic.wooden_chest
}));

const simulation = await circuit.createSimulation();
await simulation.step();
```

Это будущий служебный пример, а не уже работающий код. После шага выходной канал имеет количество 5; его имя не обязано совпадать с именем входной сети. Изменение описания не мутирует уже запущенный снимок: редактор приостанавливает прогон, а успешная пересборка создаёт/reset-ит runtime.

## Общий тип операндов

У арифметического оба свойства имеют один тип:

```text
left_operand:  Operand | OperandConst | null
right_operand: Operand | OperandConst | null
```

Объединение типов не означает смешивание полей вариантов. Каждый непустой операнд должен полностью соответствовать ровно одному из двух объектов.

### Operand: чтение сигнала

```js
{
    red: true,
    green: false,
    signal: Signal.Intermediate.iron_plate
}
```

| Поле | Требование |
|---|---|
| `red` | Обязательный `boolean` |
| `green` | Обязательный `boolean` |
| `signal` | Обязательная константа обычного сигнала либо разрешённого метасигнала |

Поле `constant` запрещено. Значения `1`, `0`, `"true"` и `"false"` не заменяют boolean. Цветовые флаги независимы для левого и правого операнда; они выбирают подключённые входы, а не задают отдельную арифметическую операцию. Оба флага `false` допустимы: выбранный набор входных сигналов пуст. Обычный канал читается как 0 и в арифметическом, и в сравнивающем; метасигналы используют правила пустого набора. Маска не равносильна незаданному операнду. Например, `A+5` при отключённых входах и выбранном выходном сигнале B даёт B=5 на следующей границе; незаданный выходной сигнал ничего не создаёт.

Общий тип объекта не разрешает все метасигналы во всех позициях. Допустимость определяется документом комбинатора; чтение входов — [моделью сетей](factorio/networks.md).

### OperandConst: числовая константа

```js
{
    constant: 5
}
```

`constant` — единственное допустимое и обязательное поле этого варианта. Значение — конечное целое число в диапазоне int32, определённом в [модели сетей](factorio/networks.md). `red`, `green` и `signal` запрещены.

Строка `"5"`, дробь, `NaN`, бесконечность и число вне диапазона отклоняются. Введённая настройка не должна молча преобразовываться в число, округляться или переполняться. Переполнение вычислений сигналов определяется отдельно в [модели сетей](factorio/networks.md).

Прямое `right_operand: 5` или `left_operand: 0` запрещено: числовой вариант всегда объект.

### null

`null` разрешён как отдельное значение обоих операндов и означает «операнд не задан». Это допустимое состояние, не числовой 0. По уточнению пользователя незаданная обработка не должна создавать выходной вклад. Для арифметического незаданный обязательный операнд оставляет выход пустым; прежний вклад после очередного шага исчезает. `{ constant: 0 }` — явно заданный числовой операнд, с которым операция выполняется.

В сравнивающем условие с `null` в любом операнде всегда ложно. Оно остаётся в выражении AND/OR: `false AND X` ложно, `false OR X` равно X. Ветка выбирается по результату всего выражения; при итоговом `false` используется `when_false`. Это правило конфигурации нашего API; `null` не подменяется игровым чтением отсутствующего канала как 0.

## Константы сигналов, операций и выход

- Сигналы доступны через дерево классов со статическими константами. Согласованный пример: `Signal.Logistic.wooden_chest` для предмета `wooden-chest`. Пользователь не повторяет `{type, name, quality}`. Группа `Logistic` организует доступ, но не заменяет игровой тип сигнала `item`.
- Для метасигналов используются `Signal.Meta.signal_each`, `Signal.Meta.signal_everything`, `Signal.Meta.signal_anything`. Группы и технические типы различаются в [каталоге](factorio/catalog.md); публичное дерево приведено ниже.
- Константы сигналов и операций должны иметь различимые типы. Если свести обе группы к произвольному `number`, необходимая проверка соответствия теряется. Сигнальные токены описаны ниже; токены операций имеют отдельный тип и владельца комбинатора.
- `operation` принимает константу операции именно своего типа комбинатора. У арифметического это `Arithmetic.Operation`: `SUM`, `SUB`, `MUL`, `DIV`, `MOD`, `POW`, `SHL`, `SHR`, `AND`, `OR`, `XOR`. Они соответствуют игровым `+`, `-`, `*`, `/`, `%`, `^`, `<<`, `>>`, `AND`, `OR`, `XOR`. `POW` — степень; `XOR` — исключающее ИЛИ. Произвольная строка `"SUM"` и операция другого устройства запрещены.
- У арифметического `return` задаёт выходной сигнал либо `Signal.Meta.signal_each`. Выход `Each` допустим только если `Each` стоит ровно в одном операнде. `Anything` и `Everything` в операнде или в `return` отклоняются. Если выходной сигнал не выбран, выходной вклад пуст: вычисленное число не создаёт канал автоматически. Отдельно подключение определяет, в какие сети попадёт выбранный выход; при обоих отключённых выходных портах в сети ничего не передаётся. Число `123`, операция и ссылка на сеть не являются выходными сигналами. Настройки выхода сравнивающего имеют отдельный контракт.
- Один объект `Arithmetic` задаёт одну игровую операцию. Функции для пользовательских вычислений внутри операндов и цепочки арифметических выражений не входят в согласованный формат.

Правила `Signal.Meta.signal_each` и сбор результатов определяются [арифметическим комбинатором](factorio/arithmetic.md). Названия метасигналов и их ID — в [едином справочнике](factorio/meta-signals.md).

### Дерево Signal

Состав разделов получен из официальных данных. Пользователь принял дерево разделов и выбор качества. По уточнению 16.11.2026 свойства сигналов именуются по prototype.name: `wooden-chest` превращается в `wooden_chest`. Знак $ и придуманные сокращения не используются; `signal-A` превращается в `signal_A`, регистр сохраняется. По решению 18.11.2026 ведущий цифровой блок до дефиса переносится в конец перед заменой дефисов: `1x2-remnants` → `remnants_1x2`, путь — `Signal.Environment.remnants_1x2`. Исходный игровой name сохраняется; коллизии после переноса также проверяются. Вложенный путь бочки длиннее трёх сегментов: `Signal.Intermediate.water_barrel.fill` и `Signal.Intermediate.water_barrel.empty`. Предмет остаётся отдельным токеном `item`, листья — отдельными токенами `recipe`. Чтение листа не меняет предмет и не запускает крафт.

| Раздел | Класс | ID группы |
|---|---|---|
| Логистика | `Signal.Logistic` | `logistics` |
| Производство | `Signal.Production` | `production` |
| Промежуточные продукты | `Signal.Intermediate` | `intermediate-products` |
| Космос | `Signal.Space` | `space` |
| Вооружение | `Signal.Combat` | `combat` |
| Жидкости | `Signal.Fluids` | `fluids` |
| Сигналы | `Signal.Signals` | `signals` |
| Враги | `Signal.Enemies` | `enemies` |
| Окружение | `Signal.Environment` | `environment` |
| Несортированное | `Signal.Unsorted` | `other` |

`Signal.Meta` отдельно предоставляет логические метасигналы, не являясь одиннадцатой игровой вкладкой. Пользовательская запись обычного сигнала имеет форму `Signal.<раздел>.<имя_сигнала>`; дополнительные ветви `Recipe` и `Entity` не вводятся. Для деревянного сундука используется только `Signal.Logistic.wooden_chest`. Игровой тип хранится внутри определения константы.

Для обычного сигнала без указанного качества используется `normal`. Явный выбор: `Signal.Logistic.wooden_chest.withQuality(Quality.RARE)` возвращает новый токен и не меняет базовую константу. `Quality.NORMAL`, `UNCOMMON`, `RARE`, `EPIC`, `LEGENDARY` обозначают модификаторы качества, а не передаваемые сигналы качества. Такие сигналы существуют отдельно среди игровых каналов. Наличие качества проверяется по профилю.

Техническое уточнение: в каталоге есть `item/wooden-chest`, `recipe/wooden-chest`, `entity/wooden-chest`. Это разные игровые идентификаторы, несмотря на совпадающую подпись. Константа `Signal.Logistic.wooden_chest` соответствует предметному сигналу `item/wooden-chest`; публичная форма API не означает объединение игровых каналов. Правило идентичности `type + name + quality` сохраняется. [SignalID](https://lua-api.factorio.com/latest/concepts/SignalID.html).

### Представление токена и первый профиль

Разделы и восемь игровых типов уже описаны выше и в [каталоге](factorio/catalog.md). Отдельный технический вопрос — что лежит за константой в JavaScript. Для обычного канала это неизменяемый зарегистрированный токен:

```js
// Иллюстрация внутренних полей, пользователь выбирает готовую константу.
{ kind: "signal", type: "item", name: "wooden-chest", quality: "normal" }
```

Метасигнал имеет другую форму: `{kind: "meta", name: "each"}` (также `everything`, `anything`). Он не превращается в канал сети. Операция — отдельный токен с типом операции и владельцем; совпадение подписи не делает её сигналом. Конструкторы принимают токены каталога, а импорт разрешает проверенный ключ через каталог; произвольный похожий объект не обходит валидацию.

Токен и вложенные данные неизменяемы. `withQuality` создаёт новый токен, проверяя профиль. Идентичность обычного канала — тройка `[type, name, quality]`; канонический строковый ключ при хранении — `JSON.stringify([type, name, quality])`. Сравнение по ссылке недостаточно: разные токены одной тройки дают один канал. Группа, подпись, иконка, имя JS-константы и количество не входят в ключ; метаданные находятся в каталоге.

Первый контур по умолчанию использует `base` из имеющегося снимка. Малые фикстуры тестов (A/B/C, сундук, железо/медь/уголь) — способ изолировать тест, а не новый урезанный каталог продукта. Формат токена сразу сохраняет все восемь типов и качество, полное дерево разделов остаётся требованием; недоступные в base записи не предлагаются. Space Age, ненормальные качества и режимы `stack-size`/`rocket-capacity` проверяются при расширении, без замены настоящих данных заглушками.

Таблица Signal 2.1.24 собрана в [data/signal-catalog/2.1.24](../../../data/signal-catalog/2.1.24/manifest.json) по правилу имён; контрольный путь — `Signal.Logistic.wooden_chest` для `item/wooden-chest`. Генератор не вводит ветви `Recipe`/`Entity` и не сливает игровые ключи. Если два доступных прототипа требуют один publicPath, путь не назначается ни одному, пока нет точечного решения. Четыре куска астероида получили путь предмета по blueprint постоянного комбинатора: `Signal.Space.metallic_asteroid_chunk` и аналоги carbonic, oxide, promethium ведут к `item/…-asteroid-chunk`. Парный `asteroid-chunk` остаётся в учёте с причиной `chooser-blueprint-item`. Поля `hide_from_signal_gui` и `item_signal_alias` в снимке отсутствуют и не подставлены. `Signal.Production.biolab` ведёт к `item/biolab`; `entity/biolab` сохранён без пути по наблюдению пользователя, без указанной версии и без подтверждения всего меню. Бочки экспортируются предметом и вложенными `.fill`/`.empty`; `entity/captive-biter-spawner` пути не получает. Для `entity/1x2-remnants` экспортирован `Signal.Environment.remnants_1x2`. Индекс путей принимает глубину больше трёх сегментов. Положительные фикстуры берут только уже экспортированные пути. Состав всего игрового меню этой таблицей не подтверждён.

### Общая запись количества сигнала

`SignalCount` — строго `{signal: SignalToken, constant: int32}`, без цветовых флагов и посторонних полей. Метасигналы в этом списке запрещены: это уже конкретный набор выходных каналов. Одна и та же запись применяется в минимальном постоянном источнике и действиях событийного блока; дубли каналов суммируются по int32, нулевой итог удаляется. В сравнивающем режим фиксированного метасигнального выхода остаётся отдельным типом с собственными правилами.

## Сравнивающий комбинатор

`Decider` использует обязательный непустой массив `conditions`. Условие содержит `left_operand`, `right_operand` и `operation`. Со второго условия обязательно поле `logic` — связка с предыдущим. У первого условия поля `logic` нет. Структурные формы операндов те же, но слева допустимы обычный сигнал, `Each`, `Everything`, `Anything` или `null`, а справа — обычный сигнал, `{ constant }` или `null`. Константа слева и метасигнал справа отклоняются. Приоритет AND/OR — в [правилах сравнивающего](factorio/decider.md).

`Decider.Operation`: `GT` `>`, `LT` `<`, `EQ` `=`, `GTE` `>=`, `LTE` `<=`, `NEQ` `!=`. `Decider.Logic`: `AND`, `OR`. Это токены операций владельца `decider`. Строка, связка вместо сравнения и константа другого комбинатора запрещены. Отсутствие `operation` или `logic` не заполняется значением по умолчанию.

Ветки `when_true` и `when_false` находятся непосредственно в конфигурации, без обёртки `outputs` и поля `return`. Их общий тип — массив выходных настроек либо `null`. Отсутствующий параметр получает `null`; `null` и `[]` означают отсутствие настроек ветки. Это согласованное значение по умолчанию не определяет смысл `null` у операнда.

### Фиксированное количество

```js
when_true: [
    {
        signal: Signal.Intermediate.coal,
        constant: 5
    }
]
```

`signal` задаёт обычный сигнал либо допустимый метасигнал, `constant` — целое int32. Количество не ограничено единицей; при добавлении настройки редактор предлагает 1. Это отдельный выходной тип с полем `signal`, а не `OperandConst`.

### Копирование количества

```js
when_false: [
    {
        signal: Signal.Intermediate.coal,
        red: true,
        green: false
    }
]
```

`red` и `green` — boolean-флаги входных цветов копирования; `constant` запрещён. Для обычного конкретного сигнала смешивание этих флагов с фиксированным количеством запрещено. Метасигнальный фиксированный выход имеет отдельную форму ниже.

### Фиксированное количество для набора каналов

Согласованный пример: выдать каждому присутствующему сигналу выбранного красного входа количество 1 при срабатывании ветки:

```js
{
    signal: Signal.Meta.signal_everything,
    constant: 1,
    red: true,
    green: false
}
```

Маска выбирает набор каналов, а `constant` — их выходное количество. Это не копирование входных количеств. Оба флага обязательны; при обоих `false` выбранный набор пуст. Аналогичные структурные настройки разрешаются только с допустимыми для данного условия метасигналами; их фильтрация определяется [справочником метасигналов](factorio/meta-signals.md). Форма объекта не отменяет ограничений `Each`/`Everything` и не объявляет сложные игровые сочетания проверенными.

`{ signal: Signal.Meta.signal_each, constant }` без маски задаёт это количество каждому каналу, прошедшему или не прошедшему выражение, по выбранной ветке. Набор берётся из условий `Each`, отдельная маска выхода не пишется. Для `Everything` и `Anything` такая запись без `red`/`green` неполна. До игрового эталона симулятор не вычисляет фиксированный метасигнал с маской и возвращает `unsupported-case`.

Вычислительная семантика режимов и ограничения метасигналов — в [сравнивающем комбинаторе](factorio/decider.md).

## Постоянный и выбирающий

Имя класса постоянного источника — `Constant`. Минимальная форма первого среза:

```js
const source = new Constant({
    red_output: red_1,
    green_output: null,
    enabled: true,
    signals: [
        { signal: Signal.Logistic.wooden_chest, constant: 5 }
    ]
});
```

`enabled` — обязательный boolean. Источник задаётся ровно одним из массивов `signals` или `sections`. Выходные порты можно пропускать, по умолчанию `null`; входы запрещены. `enabled:false` даёт пустой вклад. Источник присутствует уже на границе 0 и не накапливает количество на следующих шагах.

`signals` — массив `SignalCount`, в том числе пустой. Он равен одной активной секции без группы, с множителем 1 и фильтрами `{signal, min: constant, max: null}`.

```js
const group = new Constant.Group({
    name: "plates",
    filters: [
        { signal: Signal.Intermediate.iron_plate, min: 2, max: null }
    ]
});
const sections = new Constant({
    red_output: red_1,
    enabled: true,
    sections: [
        { active: true, multiplier: 1, group },
        {
            active: true,
            multiplier: 1,
            group: null,
            filters: [
                { signal: Signal.Signals.signal_A, min: 5, max: 10 }
            ]
        }
    ]
});
```

У секции обязательны `active`, `multiplier` и `group`. `group: null` требует `filters`; вместе с объектом группы поле `filters` запрещено. Фильтр содержит обычный сигнал, `min` и `max`. В сеть пишется `min`. `max` может быть int32 или `null` и выход не подменяет. Пустые `sections` и `filters` допустимы.

`multiplier` обязателен и поддержан только как число `1`. Другое конечное число даёт `unsupported-case`. Нечисло, `NaN` и бесконечность дают `invalid-multiplier`.

`Constant.Group` — общая изменяемая группа фильтров. Имя — непустая строка-метка; совпадение имён не объединяет объекты. `replaceFilters` заменяет список целиком и при ошибке оставляет прежний. Строка вместо объекта группы даёт `unsupported-case`. Удаления группы нет. Поля `group` и `multiplier` на самом `Constant` — неизвестные параметры.

Вклад читается при `createSimulation`. Уже созданный прогон и его `reset` сохраняют снятые количества. Следующий прогон видит текущие `enabled` и фильтры группы на границе 0, у каждой секции, которая держит этот объект. Правила вклада — в [семантике постоянного](factorio/constant.md).

Имя выбирающего — `Selector`. Обязательное поле `operation` — константа `Selector.Operation`: `SELECT`, `COUNT`, `RANDOM`, `STACK_SIZE`, `ROCKET_CAPACITY`, `QUALITY_FILTER`, `QUALITY_TRANSFER`, `QUALITY_SELECT`, `TIME`. Имена токенов совпадают с игровыми `select`, `count`, `random`, `stack-size`, `rocket-capacity`, `quality-filter`, `quality-transfer`, `quality-select`, `time`. Строка и константа другого комбинатора запрещены. Значения по умолчанию из Lua API не подставляются.

Режим читает сумму красного и зелёного входов. Поля другого режима — неизвестный параметр. Выход появляется на следующей границе, как у остальных вычисляемых устройств.

`select` требует `sort` (`Selector.Sort.DESC` или `ASC`), `index` и `compare` (`Selector.Compare`: `EQ`, `GT`, `LT`, `GTE`, `LTE`, `NEQ`). Индекс — `{ constant: int32 }` либо `{ signal }`. Нумерация рангов с 0. Один сигнал при индексе, отличном от 0, проходит целиком. Несколько сигналов и точный индекс вне диапазона дают пустой выход. Сравнение задаёт диапазон рангов. Равные значения дают `unsupported-case`.

`count` требует обычный `signal` и пишет число присутствующих каналов. Ноль канал не создаёт.

`random` требует `interval` — целое uint32 от 1. Ноль даёт `unsupported-case`: Wiki говорит об одном тике, API хранит 0. Состояние `{ rng, held, elapsed }` живёт в снимке прогона, начинается от `seed` схемы и устройства и повторяется после `restore` и `reset`. Это xorshift32 модели, не RNG Factorio. Исчезновение уже выбранного сигнала даёт `unsupported-case`.

`stack-size` и `rocket-capacity` оставляют жидкости и виртуальные сигналы без выхода. Размер стака и вес берутся из снимка 2.1.24. Предмет без веса и предмет с дробным весом дают `unsupported-case`. Вместимость ракеты для целого веса — `floor(1000000 / weight)`; результат меньше 1 не публикуется. Подъём 1000000 согласован с весом `selector-combinator` 20000 и вместимостью 50 на Wiki.

Режимы качества доступны в профиле `space-age`. Уровни — 0, 1, 2, 3, 5. `quality-filter` требует `quality` и `compare`; указатель любого качества допустим только с `EQ`. `quality-transfer` требует `source` (модификатор `Quality` или сигнал) и `destination`. Все качества цели складываются в один выходной ключ по int32. Несколько качеств сигнала-источника дают `unsupported-case`. `quality-select` требует boolean `highest`.

`time` требует контекст `Circuit({ world: { origin, dayLength } })` и хотя бы один из каналов `game_tick`, `day_tick`, `day_length`. На границе публикации `t` видны значения, прочитанные при `t - 1`: игровой тик `origin + (t - 1)`, остаток от деления на `dayLength` и сама длина. Нуль не создаёт канал. Повтор одного канала и тик выше int32 дают `unsupported-case`. Это проектная фаза, не игровой fixture.

Правила и спорные ветви — в [выбирающем](factorio/selector.md).

## Лампа, хранилище и поезда

Срез 19.11.2026 выбирает лампу и хранилище. Срез того же дня добавляет упрощённые `Station` и `Train`. Остальные подключаемые сущности не подменяются пустым устройством: неизвестный вид конфигурации отклоняется.

`Lamp` читает входы и не имеет выходов. Обязательны одно условие и boolean `use_colors`. Сравнения — `Lamp.Operation`: `GT`, `LT`, `EQ`, `GTE`, `LTE`, `NEQ`. При `use_colors: true` обязателен `color_mode`: `mapping`, `components` или `packed`. Значение по умолчанию из API не подставляется. Наблюдение `{ lit, color }` публикуется на той же границе, что и сети, которые лампа читает. Сетевой вклад пуст.

`Storage` — источник с `mode: "read"`, `enabled` и массивом `contents`. Выход есть уже на границе 0. Режимы `empty-slots`, `requests`, `enable`, `pipeline` и `temperature` дают `unsupported-case`. Входов нет.

Правила, источники и непроверенные ветви — в [лампе](factorio/lamp.md), [хранилище](factorio/storage.md) и [поездах](factorio/trains.md).

`Station` публикует присутствие, `Train` хранит маршрут по объектам станций. Длительность `transit` — целое от 1, заданное сценарием. Конфликт двух поездов на одной станции не выбирает победителя и не публикует шаг. Подробности и отличие от игры — в документе поездов.

В документации используются названия **арифметический** (`Arithmetic`), **сравнивающий** (`Decider`), **постоянный** (`Constant`), **выбирающий** (`Selector`). Прежний «решающий» означает сравнивающий.

## Основной редактор и сценарии

Основной редактор содержит только конфигурацию схемы: устройства, подключения, константы и настройки. Он открывается с корня и с `pages/configure/`. Свободная исполняемая логика выносится на отдельную страницу в сценарии [событийного комбинатора](event-combinator.md). Это дополнительный инструмент тестирования, которого нет в игре; он не заменяет четыре игровых типа. Черновик текста конфигурации живёт во вкладке браузера и не входит в файл схемы.

## Необязательные параметры

«Можно пропустить параметр» означает, что свойство отсутствует в объекте целиком. Согласовано: отсутствие любого подключения эквивалентно явно записанному `null`.

Для `when_true` / `when_false` отсутствие также означает `null`. Для вложенного `Operand` поля `red`, `green`, `signal` по-прежнему обязательны. Для остальных настроек автоматические значения по умолчанию не введены; например, отсутствие `operation` не становится `SUM`.

## Открытые вопросы

- Подготовить полную таблицу по [задаче 0002](../../tasks/0001-epic-_-f-logic-implementation/0002-task-_-signal-constant-catalog/0000-signal-constant-catalog.md). Правило имени задано: prototype.name с заменой дефиса на подчёркивание и сохранением регистра. Реальные коллизии требуют явного решения, дополнительные ветви типов исключены.
- Обязательность остальных настроек и их значения по умолчанию. Подключения и выходные ветки можно пропускать; обязательные поля операндов определены выше.
- Секции постоянного и контракт условий `Decider` определены выше. Контракт выбирающего определён выше. Ограничения арифметического переносятся только там, где это сказано явно.
- Для сравнивающего пропущенный `constant` или неполная маска не получают игровое значение по умолчанию: выход — ровно одна из форм выше. Неполная запись отклоняется.
- Формат описания конфигурации основного редактора зафиксирован в [редакторе](editor.md): обычные комбинаторы записываются вызовом `Arithmetic({...})` и так же для `Constant`, `Decider`, `Selector`. Прежние декларации `new Класс({...})` читаются. Разбор не вызывает `eval` и собирает те же объекты классов. Свободный JavaScript остаётся на странице сценария.
- Контракт первого среза событийного блока уточнён в [отдельном документе](event-combinator.md). Изменения этого API обсуждать там, не хранить второй список незаданных аргументов.

Непроверенные случаи поведения игры хранятся в документах соответствующих комбинаторов, отдельно от вопросов формы API.
