Карта согласованных требований и справочник для разработки. Документы описывают требуемое поведение; приложение ещё не реализовано.

При изменении правила обновлять его основной документ. В остальных местах оставлять ссылки; краткое пояснение контекста и примеры диагностики допустимы, но не должны становиться вторым определением правила.

## Статус сведений

- **Согласованный контракт** задаёт выбранное поведение нашего проекта, например форму операндов и веток API.
- **Правило игры** снабжено ссылкой на официальную Wiki или API Wube. Сверка источника не равна проверке запуском игры.
- **Контрольное ожидание** иллюстрирует правило; это не отчёт о пройденном тесте приложения.
- **Открытый вопрос API** хранится в `api.md`; ещё не согласованную форму или default нельзя придумывать при реализации.
- **Непроверенный игровой случай** хранится рядом с семантикой комбинатора, к которому относится. До получения эталона не заявлять его проверенным.

Актуальная целевая версия и журнал сверки находятся в [совместимости](compatibility.md). Версия конкретного снимка данных остаётся указана в каталоге и manifest; она не заменяет правило выбора новой stable.
