# Сравнивающий комбинатор

Сочетания логических метасигналов повторно сверены по официальным источникам **14 ноября 2026 года**, stable **2.1.24**. Проверки запуском игры не выполнялись; спорные сочетания перечислены отдельно в [справочнике метасигналов](meta-signals.md).

## Условия

Сравнения: `>`, `<`, `=`, `>=`, `<=`, `!=`. Условие сопоставляет первый сигнал со вторым сигналом либо константой; у сигнальных операндов выбираются входные цвета. Условия объединяются `AND` и `OR`, причём `AND` имеет приоритет. [Описание](https://wiki.factorio.com/Decider_combinator), [структура условия](https://lua-api.factorio.com/latest/concepts/DeciderCombinatorCondition.html).

Проектная проверка приоритета: `A>0 OR B>0 AND C>0` трактуется как `(A>0) OR ((B>0) AND (C>0))`.

Уточнения конфигурации нашего API: `null` в любом операнде делает данное условие ложным; оно не удаляется из выражения. При обоих выключенных цветах читается пустой набор: обычное `A=0` истинно, `A>0` ложно. Это отличается от незаданного операнда. Для `Each`, `Everything`, `Anything` на пустом наборе действуют их отдельные правила; список кандидатов нельзя заменять одним числом 0. Ветка определяется итогом всего выражения. Формы объектов — в [API](../api.md); возможность настройки пустой маски в игровом UI ещё не подтверждена.

## Выходы

Игровой API содержит `conditions`, `outputs`, `else_outputs`. Для текущей stable-базы обычные выходы срабатывают при истинном условии, `else` — при ложном. Каждый выход выдаёт настроенную константу либо значение своего выходного сигнала с выбранных входных сетей. Это не обязательно значение левой части сравнения. [Параметры](https://lua-api.factorio.com/latest/concepts/DeciderCombinatorParameters.html), [выход](https://lua-api.factorio.com/latest/concepts/DeciderCombinatorOutput.html).

Соответствие игровым `outputs` / `else_outputs` в нашем API — ветки `when_true` / `when_false`. Форма объектов и значения по умолчанию определены в [API](../api.md). Здесь описывается поведение выбранных веток.

Например, при `A>0 → B, input count`, `A=5, B=9` результат — `B=9`. Если B отсутствует, копируется 0. Константный выход может быть отличен от 1.

### Фиксированное количество

Для целевой версии фиксированное количество настраивается: значение 1 является игровым значением по умолчанию, а не единственным допустимым. Изменение выходной константы добавлено в Factorio 2.0.36. В API этот режим соответствует `copy_count_from_input: false` и полю `constant` типа int32. [История изменения](https://wiki.factorio.com/Decider_combinator#History), [официальные параметры](https://lua-api.factorio.com/latest/concepts/DeciderCombinatorOutput.html).

Форма настройки фиксированного количества — в [объектном API](../api.md). Возможность количества, отличного от 1, подтверждена пользователем для модели проекта 14 ноября 2026 года.

Например, настройка фиксированного угля=5 при срабатывании соответствующей ветки и обычных сигнальных условиях выдаёт уголь=5, даже если угля во входах нет. Выходной сигнал обозначает один канал, а не цвет провода: красный виртуальный сигнал не означает все каналы красной сети. Для фиксированного выхода одного конкретного сигнала входные цвета не являются источником количества.

### Копирование входного количества

В режиме копирования передаётся количество выбранного выходного сигнала с выбранных входных цветов. Количество не заимствуется у сигнала, который сделал условие истинным. При выборе обоих цветов одноимённые каналы складываются. [Параметры копирования](https://lua-api.factorio.com/latest/concepts/DeciderCombinatorOutput.html).

Для обычного выражения `(железо > 100 AND медь < 50) OR A = 1`, если A=1, копирование угля выдаёт его входное количество; если угля на выбранных входах нет, выходного канала угля нет. В режиме фиксированного количества при том же условии выход угля может быть создан независимо от наличия угля на входе.

Фиксированное количество и копирование — разные способы формирования выхода. Не переносить выбор цветов копирования в поля фиксированного выхода обычного сигнала. Сетевые маски и правила присутствия каналов для метасигнальных выходов рассматриваются отдельно: их нельзя вывести только из примера одного конкретного сигнала.

## Логические метасигналы

Правила `Each` — каждый, `Everything` — все и `Anything` — любой, матрица допустимых выходов, примеры поканальной проверки и сложные случаи собраны в [спецификации метасигналов](meta-signals.md). Это основной документ данных правил; отдельную расходящуюся матрицу здесь не поддерживать.

Для движка существенно различие: обычное выражение выбирает ветку целиком, а выражение с `Each` требует сохранить результат для каждого канала. Нельзя заменить эту обработку одним общим boolean.

## Проверки

- Конкретный отсутствующий A читается как 0, поэтому обычное `A=0` истинно.
- Обычный и `else`-выходы взаимоисключающи для простого условия.
- При обычном истинном условии фиксированный выход угля=5 создаётся и при отсутствии угля на входах; аналогичный выход угля=1 не является единственным разрешённым количеством.
- При том же условии копирование отсутствующего угля даёт пустой выход; копирование угля=15 даёт уголь=15.

Контрольные примеры и неуточнённые сочетания метасигналов — в их [спецификации](meta-signals.md). Повторные выходы одного канала и составные условия также требуют эталонных схем в игре.

Общая задержка и публикация — [выполнение по тикам](ticks.md).
