# Выбирающий комбинатор

## Режимы текущей базы

Идентификаторы девяти операций определены в [API](https://lua-api.factorio.com/latest/concepts/SelectorCombinatorParameterOperation.html). Их назначение описано в [Selector combinator](https://wiki.factorio.com/Selector_combinator).

| Режим | Действие |
|---|---|
| `select` | Сортирует по значению и выбирает сигнал по индексу с сохранением значения |
| `count` | Выдаёт количество разных входных сигналов на заданном канале |
| `random` | Выбирает входной сигнал через настраиваемый интервал тиков |
| `stack-size` | Для предметов выдаёт размер стака, независимо от входного количества |
| `rocket-capacity` | Выдаёт допустимое количество предмета в ракете |
| `quality-filter` | Пропускает сигналы, удовлетворяющие сравнению качества |
| `quality-transfer` | Переносит заданное или входное качество на целевой сигнал |
| `quality-select` | Для каждого типа оставляет наибольшее или наименьшее входное качество |
| `time` | Выдаёт игровой тик, тик суток и длину суток |

Режимы дополнения и качества доступны только в соответствующем профиле данных; их наличие в API не означает доступность любой конфигурации без дополнений.

## Существенные параметры

Для `select` задаются направление сортировки, индекс из константы/сигнала и сравнение индекса. Нумерация с 0. Сравнение позволяет выбрать диапазон рангов. Для `count` задаётся выходной канал; для `random` — интервал; для качества — фильтр, источник и назначение; для `time` — три выходных канала. [Параметры](https://lua-api.factorio.com/latest/concepts/SelectorCombinatorParameters.html).

Wiki указывает особый случай `select`: единственный входной сигнал пропускается и при индексе вне диапазона; при нескольких сигналах и точном индексе вне диапазона выход пуст. Равные значения требуют отдельной проверки порядка разрешения. `stack-size` и `rocket-capacity` не должны превращать жидкости и виртуальные сигналы в предметы. [Правила выбора](https://wiki.factorio.com/Selector_combinator).

## Проектная модель

Случайный режим хранит внутреннее состояние и использует воспроизводимый генератор с явным seed. История сохраняет его состояние. Это обеспечивает повторяемость нашего симулятора; совпадение последовательности с RNG Factorio пока не заявляется.

`time` читает время симуляции, а не часы компьютера. Длину суток и исходное время передавать в контексте мира; не зашивать одно значение для всех планет. Каталог предметов хранит размеры стаков и ракетные ограничения для выбранной stable-версии.

## Проверки и неуточнённые границы

- `count` для `A=100, B=-2` считает два канала, а не сумму 98.
- `select` проверяется для пустого входа, одного сигнала, отрицательных значений, равенства значений и диапазона рангов.
- Для `random` проверить границу интервала, исчезновение выбранного сигнала и первый выбор. Wiki и API по-разному представляют значение интервала по умолчанию; нормализацию подтвердить в игре.
- Для качества проверить объединение выходов после переноса в одинаковый ключ.
- Для `time` проверить точную фазу считывания и переполнение значения тика.
- Для всех режимов сверить задержку и поведение при изменении входов на каждом тике; общего наличия поля в API для этого недостаточно.

## Проектная модель

Форма `Selector` задана в [API](../api.md). Проверка stable **19.11.2026**: `stable.alpha = stable.expansion = 2.1.24`. Запуск игры для этих режимов не выполнялся. Ожидания ниже — модель симулятора.

Устройство читает сумму подключённых красного и зелёного входов и публикует вклад на следующей границе. Пустой вход даёт пустой выход во всех режимах, кроме `time`: время берётся из контекста мира. Ноль после нормализации канал не создаёт.

`select` сортирует присутствующие каналы по значению. `DESC` ставит большее первым, `ASC` — меньшее. Ранг 0 — первый в этом порядке. Сравнение `Selector.Compare` оставляет ранги, удовлетворяющие индексу. Если сигнал один и индекс не равен 0, наружу проходит он сам: так читается особый случай Wiki про индекс вне диапазона. При нескольких сигналах точный индекс вне `0 … n-1` оставляет выход пустым. Два канала с одним значением дают `unsupported-case`: порядок равенства Wiki не фиксирует.

`count` пишет число разных присутствующих каналов на заданный сигнал. Значения каналов не складываются.

`random` хранит в снимке устройства `{ rng, held, elapsed }`. Начальный `rng` — `initialRng(seed схемы, id устройства)`. Пока выбора нет, выход пуст, а `elapsed` растёт, только если вход непуст; пустой вход обнуляет ожидание. Когда `elapsed` достигает `interval`, выбирается канал и сразу публикуется, счётчик становится 0. Пока выбор удерживается, публикуется его текущее значение. На тике очередного порога публикуется новый выбор. Кандидаты упорядочены по ключу канала, номер берётся как `xorshift32(rng) % n`. Совпадение с RNG Factorio не заявляется. `interval: 0` и исчезновение уже выбранного канала — `unsupported-case`.

`stack-size` заменяет количество предмета размером стака из `items.json` профиля, сохраняя ключ канала, включая качество. Жидкость и виртуальный сигнал пропускаются. `rocket-capacity` делает то же для целого веса: `floor(1000000 / weight)`. Вес 20000 у `selector-combinator` даёт 50, как на Wiki. Нет веса или дробный вес — `unsupported-case`. Вместимость меньше 1 не публикуется: так в снимке остаются атомная бомба и ракетная шахта.

Качество сравнивается по уровню снимка Space Age: normal 0, uncommon 1, rare 2, epic 3, legendary 5. В `base` три режима качества дают `unavailable-mode`. Фильтр оставляет каналы, чьё сравнение с заданным уровнем истинно. Равенство указателю любого качества оставляет все присутствующие каналы; иное сравнение с ним отклоняется. Перенос складывает все качества целевого предмета в один ключ с качеством источника. Если источник — сигнал и на входе у него больше одного качества, шаг получает `unsupported-case`. Выбор качества оставляет для пары `type + name` наибольший или наименьший уровень и его количество.

`time` не читает часы компьютера. Контекст схемы — `origin` и `dayLength`, оба int32, длина от 1. Вычисление на опубликованной границе `s` берёт игровой тик `origin + s`; наружу он попадает на границе `s + 1`. Остаток суток — `gameTick % dayLength`. Переполнение int32 и запись двух показаний в один канал — `unsupported-case`. Фаза `origin + s` — проектное правило задержки, не подтверждённый игровой fixture.
