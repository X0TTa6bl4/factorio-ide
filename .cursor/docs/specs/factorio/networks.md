# Сети и сигналы

Проверено по официальным источникам **14 ноября 2026 года** для stable **2.1.24**. Это справочник поведения игры и отдельно обозначенная модель симулятора; проверки в самой игре в рамках этой редакции не выполнялись.

## Правила игры

Связанные провода одного цвета образуют общую сеть. Красная и зелёная сети самостоятельны. На одном канале складываются значения всех источников; отсутствующий канал читается как ноль. Числа — знаковые 32-битные целые с переполнением: `2147483647 + 1 = -2147483648`. [Circuit network](https://wiki.factorio.com/Circuit_network).

Операнд может читать красный вход, зелёный или их сумму. Выбор цвета не объединяет сети физически. В текущем API предусмотрены также маски цветов выхода; по умолчанию используются оба цвета. [Выбор входа](https://lua-api.factorio.com/latest/concepts/ArithmeticCombinatorParameters.html), [цвета выхода](https://lua-api.factorio.com/latest/classes/LuaControlBehavior.html).

Идентичность сигнала включает `type`, `name`, `quality`; качество по умолчанию — `normal`. API различает типы `item`, `fluid`, `virtual`, `entity`, `recipe`, `space-location`, `asteroid-chunk`, `quality`. Не ограничивать формат только буквами A–Z или именем предмета. [SignalID](https://lua-api.factorio.com/latest/concepts/SignalID.html), [SignalIDType](https://lua-api.factorio.com/latest/concepts/SignalIDType.html).

`Each`, `Anything`, `Everything` — режимы обработки сигналов, а не передаваемые каналы. Их семантика — в [сравнивающем](decider.md). [Обучение комбинаторам](https://wiki.factorio.com/Combinator_Tutorial).

### Что складывается

Сеть передаёт таблицу независимых числовых каналов. Складываются вклады с одинаковой идентичностью сигнала, а не все числа сети в одно число. Для отсутствующего вклада используется 0. Такой принцип действует и для нескольких источников в одной сети, и при чтении двух входных цветов. [Шина сигналов](https://wiki.factorio.com/Combinator_Tutorial#Introduction).

Контрольный пример проекта; предметы имеют качество `normal`:

| Канал | Красная сеть R | Зелёная сеть G | Чтение R и G |
|---|---:|---:|---:|
| Железная плита | 10 | 3 | 13 |
| Медная плита | 4 | 0 | 4 |
| Уголь | 0 | 7 | 7 |

Медь и уголь сохраняются на собственных каналах. Сумма всех количеств, 24, не возникает как отдельный результат автоматически. Если железо разных качеств, это разные каналы: оно не складывается в один сигнал. Ключ канала — `type + name + quality`. [SignalID](https://lua-api.factorio.com/latest/concepts/SignalID.html).

Формальная запись для нашей модели чтения, где `s` — один полный ключ сигнала:

```text
read({red}, s)        = R[s]
read({green}, s)      = G[s]
read({red, green}, s) = int32(R[s] + G[s])
```

Если итог канала равен нулю, обычное чтение даёт 0; в перечне присутствующих каналов симулятор его не хранит. Отрицательный итог сохраняется. Это важно при последующей обработке `Each`.

### Три уровня, которые нельзя смешивать

1. Соединения определяют, к каким физическим сетям присоединены входные и выходные клеммы.
2. Маска входных цветов определяет, какие из подключённых сетей читает конкретный операнд. Это независимый выбор для левого и правого операнда.
3. Выбор сигнала определяет, какое значение извлекается из выбранных сетей: обычный канал либо допустимый для устройства метасигнал.

Разделение маски и сигнала непосредственно отражено в API: `first_signal` / `first_signal_networks` и `second_signal` / `second_signal_networks`. Числовые операнды задаются отдельно через `first_constant` / `second_constant`. [ArithmeticCombinatorParameters](https://lua-api.factorio.com/latest/concepts/ArithmeticCombinatorParameters.html).

Выбор цветов не является операцией арифметического комбинатора: сначала формируются значения операндов, затем над ними выполняется настроенная операция.

### Независимые маски операндов

В API у каждого сигнального операнда своя пара флагов `red` / `green`; по умолчанию оба флага включены. [CircuitNetworkSelection](https://lua-api.factorio.com/latest/concepts/CircuitNetworkSelection.html).

Пример, в котором левый операнд читает только R, правый — R и G, а арифметическая операция выполняется после подготовки обоих значений, приведён в [арифметическом комбинаторе](arithmetic.md).

### Соединения и обратные связи

Красный и зелёный цвета не сливаются в одну физическую сеть от того, что устройство читает оба. Отдельные несвязанные сети одного цвета тоже остаются отдельными. Повторный провод внутри уже связной сети не дублирует источник. [Физическая структура](https://wiki.factorio.com/Circuit_network#Physical_network_structure).

Входная и выходная стороны вычисляемого комбинатора разделены. Выход можно проводом соединить со входом; тогда это общая сеть соответствующего цвета и возникает обратная связь с задержкой устройства. Сетевые сигналы обновляются после вычислений устройств, а не рекурсивно по проводам. [Обновление по тикам](https://wiki.factorio.com/Combinator_Tutorial#Introduction). Наши буферы и момент публикации описаны в [спецификации тиков](ticks.md).

## Проектная модель

- `networks[]`: стабильный ID, цвет, опубликованная таблица `current` и рабочая таблица `next`.
- У вычисляемого устройства: `input.red`, `input.green`, `output.red`, `output.green`; значение ссылки — ID либо `null`.
- У постоянного источника входов нет. Прямая связь выхода со входом допустима.
- Ключ таблицы сигналов — полная идентичность. Нулевые итоги не хранятся, отрицательные значения сохраняются.
- Несколько проводов одной связной сети не дают повторного вклада источника. Два отдельных цветовых канала, напротив, могут дать удвоение при чтении их суммы.
- Проводные соединения редактора хранить отдельно от вычисленных сетей: удаление провода может разделить сеть, а добавление — объединить.

Стабильный ID не равен позиции в массиве. Сериализация использует ID, не циклические объектные ссылки. Не смешивать сетевые суммы с собственными выходами устройств: по сумме нельзя восстановить вклад каждого источника.

## Числа в JavaScript

Все вычислительные результаты нормализуются к int32. Умножение больших int32 нельзя безусловно реализовывать через `a * b` с последующим приведением: промежуточное целое может выйти за точность `Number`. Подходящий вычислительный примитив нужно выбрать и проверить отдельно; степень также требует точной спецификации пограничных случаев.

## Контрольные примеры

| Сценарий | Ожидаемый результат |
|---|---|
| Два источника `A=3`, `A=7` | В сети `A=10` |
| `A=3` и `A=-3` | Канала A нет, чтение A даёт 0 |
| Красный `A=2`, зелёный `A=5` | Оба входа дают 7; только красный — 2 |
| R: железо=10, медь=4; G: железо=3, уголь=7 | Чтение обоих: железо=13, медь=4, уголь=7 |
| R: `A=3`, G: `A=-3`; чтение обоих | A отсутствует в результирующем перечне, обычное чтение A даёт 0 |
| Повторный провод той же сети | Значение не удваивается |
| Одинаковый предмет разных качеств | Разные ключи сигнала |

## Что ещё сверять в игре

- Граничные случаи `Each` с разными масками двух операндов и взаимным обнулением каналов — по контрольным схемам из [арифметического](arithmetic.md).

- Изменение проводов и настроек во время выполнения не входит в начальный контракт симулятора: пока используется сброс согласно [спецификации тиков](ticks.md).
