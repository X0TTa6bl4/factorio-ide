# Метасигналы и служебные символы

Русские и английские названия ниже согласованы пользователем и используются последовательно в документации, подсказках и диагностике редактора. Для машинной обработки использовать стабильные игровые ID.

Правила логических метасигналов повторно сверены по официальной Wiki и API **14 ноября 2026 года**, целевая stable — **2.1.24**. Проверка запуском игры не выполнялась; контрольные примеры ниже являются ожиданиями по документации.

## Логические метасигналы

| Английское название | Русское название | Константа объектного API | Игровой ID |
|---|---|---|---|
| `Each` | каждый | `Signal.Meta.signal_each` | `signal-each` |
| `Everything` | все | `Signal.Meta.signal_everything` | `signal-everything` |
| `Anything` | любой | `Signal.Meta.signal_anything` | `signal-anything` |

Эти названия обозначают три разных режима. «Каждый» нельзя использовать как синоним «все». Имена констант показывают принятую форму API; способ их экспорта и техническое представление ещё предстоит определить.

Они относятся к `virtual-signal` в определениях игры, но являются режимами настройки комбинатора и не передаются по сети как три обычных числовых канала. Правила выхода отличаются от проверки условия: см. [сравнивающий](decider.md) и [арифметический](arithmetic.md) комбинаторы. [Официальное описание](https://wiki.factorio.com/Combinator_Tutorial#Logic_signals).

В данных присутствуют в обоих профилях с ролью `logic-selector`. Машинный список — [special-signals.json](../../../../data/factorio/2.1.24/special-signals.json).

## Присутствующие каналы

Метасигналы работают с каналами, а не только с предметами: применяются также к жидкостям, виртуальным и другим обычным сигналам поддержанного каталога. Разные качества одного предмета имеют разные ключи. Они не перебирают весь каталог игры. Идентичность и поканальное суммирование описаны в [модели сетей](networks.md).

После объединения выбранных входных цветов присутствующим считается канал с ненулевым итогом. Отрицательные значения тоже участвуют. Отсутствующий обычный канал читается как 0, но не появляется из-за этого в переборе метасигнала. [Логические сигналы](https://wiki.factorio.com/Circuit_network#Logic_signals).

## Каждый — Each в сравнивающем

В сравнивающем комбинаторе `Each` в условии означает отдельную оценку выражения для каждого присутствующего канала. Если `Each` используется хотя бы в одном условии, движок должен сохранять результат по каналам, а не сводить всё к одному boolean. При нескольких условиях канал должен пройти всё выражение с его AND/OR, а не обязательно каждое отдельное сравнение. [Функция сравнивающего](https://wiki.factorio.com/Decider_combinator#Function).

Выход `Each` допустим только при наличии `Each` в условиях. Для `when_true` выбираются прошедшие каналы; для `when_false` — каналы, для которых выражение ложно. Копирование сохраняет их количества с выбранных входов; фиксированный выход задаёт каждому выбранному каналу настроенное количество. Режим количества и выбор каналов — отдельные настройки. [Each wildcard](https://wiki.factorio.com/Combinator_Tutorial#Each_wildcard), [параметры выхода](https://lua-api.factorio.com/latest/concepts/DeciderCombinatorOutput.html).

Вход контрольного примера: железо=150, медь=50, уголь=200. Все условия и копирование используют один и тот же набор входных цветов.

| Условие | Выход | Ожидание |
|---|---|---|
| `Each > 100` | `when_true`: Each, копирование | железо=150, уголь=200 |
| `Each > 100` | `when_false`: Each, копирование | медь=50 |
| `Each > 100` | `when_true`: Each, фиксированное 1 | железо=1, уголь=1 |
| `Each > 100 AND Each < 200` | `when_true`: Each, копирование | железо=150 |
| `Each > 100` | `when_true`: A, фиксированное 1 | A=2 — по одному вкладу за прошедший канал |
| `A = 1` без Each | Each | Ошибка конфигурации |

Дополнительный контроль присутствия и знака: при входе A=3, B=-2 условие `Each > 0` и выход `Each` с копированием оставляют только A=3. Так проверяется фильтрация отрицательного присутствующего канала, а не только сравнение положительных количеств.

Пустой вход не создаёт кандидатов для `Each`. Он не порождает значения всех отсутствующих сигналов даже при сравнении `Each = 0`. Обычное условие `A = 0` на пустом входе, напротив, истинно. [Присутствие каналов при Each](https://wiki.factorio.com/Circuit_network#Each).

Вычисление `Each` и сбор результатов в арифметическом устройстве определяются в [его отдельной спецификации](arithmetic.md); условия сравнивающего на арифметический не переносятся.

## Все — Everything

На входе сравнивающего `Everything` проверяет, что все присутствующие каналы удовлетворяют сравнению; на пустом входе такое сравнение истинно. На выходе он выбирает все присутствующие каналы выбранных входов при срабатывании соответствующей ветки. Выход `Everything` несовместим с наличием `Each` в условиях. [Everything wildcard](https://wiki.factorio.com/Combinator_Tutorial#Everything_wildcard).

Это общий пропуск набора, а не поэлементный фильтр. Например, при A=1, железо=150 и медь=50 условие `A = 1` и выход `Everything` с копированием пропускают все три канала, хотя железо и медь не упоминались в условии.

## Любой — Anything

На входе сравнивающего `Anything` проверяет существование хотя бы одного подходящего присутствующего канала; на пустом входе сравнение ложно. На выходе выбирается один подходящий канал. Его нельзя выбирать случайно или по порядку добавления ключей JavaScript: нужен игровой порядок сигналов. [Anything](https://wiki.factorio.com/Circuit_network#Anything).

Если справа от входного `Anything` или `Everything` задан обычный сигнал, он исключается из проверяемых ими каналов. Для `Each` такого исключения нет. Разные маски и смешанные условия требуют отдельных эталонов; это правило не заменяет проверку всех сочетаний.

## Допустимые выходы сравнивающего

| Выход | В условиях нет Each | В условиях есть Each |
|---|---|---|
| Конкретный сигнал | Допустим | Допустим, вклады поканальных результатов суммируются |
| `Each` — каждый | Запрещён | Допустим |
| `Everything` — все | Допустим | Запрещён |
| `Anything` — любой | Допустим | Допустим |

Матрица основана на [таблице выходов сравнивающего комбинатора](https://wiki.factorio.com/Decider_combinator#Function). Проверка допустимости не означает одинаковую семантику этих выходов. Для каждой записи выходной ветки требуется отдельная проверка.

В сравнивающем входные логические метасигналы относятся к левой стороне сравнений. Нельзя автоматически разрешать их в правом операнде только на основании общего типа `Operand`. Актуальные подсказки зависят от устройства и позиции поля. В арифметическом единственный `Each` может находиться в одном из двух операндов. [Описание логических сигналов](https://wiki.factorio.com/Circuit_network#Logic_signals), [арифметические операнды](https://wiki.factorio.com/Arithmetic_combinator#Function).

## Что ещё сверять в игре

- Разные входные маски нескольких условий с `Each`: состав множества кандидатов и чтение их значений.
- Различающиеся маски проверки и копирования выходного `Each`, в том числе нулевые значения на выбранном выходом входе.
- Смешанные `Each`/`Anything`/`Everything`, OR-ветки и `when_false` на сложных выражениях.
- Точный выбор выходного `Anything` для обоих ветвлений и сложных выражений, совпадение с порядком Factoriopedia.
- Конкретный выходной сигнал в режиме копирования при наличии входного `Each` и несколько выходов на один канал.
- Маски присутствия каналов при фиксированном количестве метасигнального выхода. Не считать доказанным, что им вообще не нужен выбор входов: таблица Wiki разрешает выбор проводов для ряда таких выходов даже при фиксированном количестве.

До получения игровых эталонов не выдавать эти случаи за проверенные и не подменять их упрощением до одного общего условия. Симулятор возвращает для них `unsupported-case`: спорная конфигурация — до запуска, непустой выбор выходного `Anything` и повтор канала в одном тике — при шаге. Контрольные примеры `Each`, `Everything` и исключения правого сигнала выше остаются проектной моделью по документации, а не игровым fixture.

## Указатель любого качества

`signal-any-quality` добавляется штатным пакетом `quality`, поэтому присутствует в профиле Space Age и отсутствует в base. Роль в каталоге — `quality-selector`. Это не шестой уровень качества: уровни отдельно перечислены в `qualities.json`. Допустимость этого указателя зависит от поля настройки; обычную передачу по каналу отдельно не подтверждали.

## Параметры чертежей

`parameter-0` … `parameter-9` — заполнители параметризованных чертежей. Их нужно отличать по типу: одинаковые имена существуют у предметов, жидкостей, рецептов и сущностей; Space Age добавляет астероидные фрагменты. В каждом профильном файле они помечены `parameter=true`, `role=blueprint-parameter`.

Они не имеют обычного игрового действия. Возможность показывать их в списках определяется настройкой игры для подготовки чертежей. [Параметры прототипа](https://lua-api.factorio.com/latest/prototypes/PrototypeBase.html#parameter), [параметризация чертежей](https://wiki.factorio.com/Blueprint#Parameterisation).

## Служебные иконки и операторы

`signal-unknown` и аналогичные `*-unknown` — скрытые заглушки отсутствующего прототипа, не дополнительные метасигналы логики. Они сохранены для диагностики с ролью `internal`.

Знаки `+`, `-`, `*`, `/`, `%`, `^`, `<<`, `>>`, `AND`, `OR`, `XOR` и сравнения `=`, `!=`, `<`, `>`, `<=`, `>=` — операции, а не элементы каталога сигналов. Их спецификация находится в документах соответствующих комбинаторов.

Фактический список прототипов взят из `base/prototypes/signal.lua`, `quality/prototypes/signal.lua`, `core/prototypes/unknown.lua` и генерации параметров официальной сборки; его не следует дополнять выдуманными каналами.
