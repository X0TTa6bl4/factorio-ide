# Арифметический комбинатор

Сетевое чтение и параметры повторно проверены по официальным источникам **14 ноября 2026 года**, stable **2.1.24**. Числовые примеры ниже — контрольные ожидания из описанных правил, не результаты запуска Factorio.

## Операции и параметры

Операция принимает два операнда и задаёт выходной сигнал. Операнд — константа или сигнал с выбором красной, зелёной либо обеих входных сетей. Отсутствующий обычный сигнал имеет значение 0. [Параметры API](https://lua-api.factorio.com/latest/concepts/ArithmeticCombinatorParameters.html).

| Операция | Идентификатор API |
|---|---|
| Сложение, вычитание | `+`, `-` |
| Умножение, деление | `*`, `/` |
| Остаток, степень | `%`, `^` |
| Сдвиг влево, вправо | `<<`, `>>` |
| Побитовые И, ИЛИ, исключающее ИЛИ | `AND`, `OR`, `XOR` |

В игровом API `^` — степень; XOR обозначен отдельно. В JavaScript `^` означает XOR, поэтому прямое исполнение текста игровой операции недопустимо. [Идентификаторы операций](https://lua-api.factorio.com/latest/concepts/ArithmeticCombinatorParameterOperation.html).

## Числовые правила

- Деление отбрасывает дробную часть к нулю: `-21 / 10 = -2`.
- Остаток имеет знак делимого: `-13 % 3 = -1`.
- Правый сдвиг арифметический, с сохранением знака.

Эти правила описывает [Arithmetic combinator](https://wiki.factorio.com/Arithmetic_combinator). Общие сеть, цвета и int32 — [в документе сетей](networks.md); задержка — [в документе тиков](ticks.md).

## От сетей к результату

Для проектного представления каждый операнд — один из вариантов:

```text
Constant(value: int32)
Signal(signalId, inputColors)
Each(inputColors)
```

`inputColors` выбирает красный вход, зелёный или оба. Эта маска и выбор канала — разные настройки; списка сетей недостаточно для определения операнда. Для константы маска не нужна. Настройки устройства не дают права читать произвольную сеть проекта: используются подключённые входы.

Пример с масками, по [описанию параметров API](https://lua-api.factorio.com/latest/concepts/ArithmeticCombinatorParameters.html):

```text
R: железо=10, медь=4
G: железо=3, уголь=7

left  = Signal(железо, {red})        → 10
right = Signal(железо, {red, green}) → 13
operation = +
outputSignal = A                    → A=23
```

При выборе двух цветов значения одноимённого канала складываются до операции. Сумма `R+G` здесь не означает выполнение второй арифметической операции и не превращает остальные каналы в отдельные результаты.

## Режим Each и выход

`Each` допускается максимум в одном из двух операндов; выход `Each` требует такого операнда. Для обычных операндов вычисляется одно число; конкретный выходной сигнал задаёт, на каком канале его передать. При одном `Each` выполняется обработка присутствующих каналов выбранного для него входа. Выход `Each` сохраняет идентичности обработанных каналов, конкретный выходной сигнал собирает результаты в один канал. `Everything` и `Anything` не заменяют `Each` в арифметическом устройстве. [Функция арифметического комбинатора](https://wiki.factorio.com/Arithmetic_combinator#Function).

Контрольные примеры с теми же R и G:

| Операнды и операция | Выход | Ожидание |
|---|---|---|
| `Each({red, green}) + 0` | `Each` | железо=13, медь=4, уголь=7 |
| `Each({red}) + 0` | `Each` | железо=10, медь=4 |
| `Each({red, green}) * 2` | `Each` | железо=26, медь=8, уголь=14 |
| `Each({red, green}) * 2` | A | A=48 |
| `Signal(железо, {red}) + Signal(железо, {red, green})` | A | A=23 |

Следовательно, перенести объединённые входные сигналы с суммированием одинаковых можно настройкой `Each` на обоих цветах, операцией `+ 0` и выходом `Each`. Операция над двумя произвольными таблицами сигналов, например `Each(R) + Each(G)`, не вводится как возможность одного игрового арифметического комбинатора.

Поле `return` объектной конфигурации задаёт выходной канал/режим. Числовая константа на выходе вместо результата не является аналогом `output_signal`: например, для фиксированного `A=5` можно задать операцию `2+3` и выход A.

## Связь с объектным API

Форма `Arithmetic`, общие типы операндов и выходное поле `return` определены в [контракте API](../api.md). Этот документ задаёт только их вычислительный смысл. Чтение отключённых входов или маски `false/false` — пустая таблица, обычного сигнала в ней — 0. Незаданный `null`-операнд отличается от такого чтения и описан отдельно в API.

Согласованный пример: `A+5`, отключённые входы, выходной сигнал B дают B=5. Для передачи в сеть также нужен подключённый выходной порт. Если выходной сигнал не выбран, число 5 само по себе не создаёт никакого канала. Это не меняет `Each`: на пустом наборе у него нет каналов для перебора.

## Проектные проверки

| Случай | Результат |
|---|---|
| Вход `A=3`, операция `A+2 → B` | `B=5` на следующей границе |
| Входы отключены, обычный операнд A, `A+5 → B` | `B=5` на следующей границе при подключённом выходе |
| То же вычисление без выбранного выходного сигнала | Пустой выход |
| `A=3, B=-2`, `Each*2 → Each` | `A=6, B=-4` |
| Тот же вход, `Each*2 → C` | `C=2` |
| `A=3`, `Each+1 → Each` | Меняется A; отсутствующие каналы не создаются |
| `-8 >> 1` | `-4` |
| `A=1, B=1, C=1`, `Each*10 → Each` | `A=10, B=10, C=10` |
| Тот же вход, `Each*10 → B` | Только `B=30`: складываются результаты всех трёх каналов |

Два примера `Each*10` дополнительно разобраны и подтверждены пользователем; это не заменяет запуск эталонной схемы в игре.

До заявления полной совместимости проверить в stable-игре: деление и остаток на ноль, `INT_MIN / -1`, отрицательную/нулевую степень, переполнение степени, отрицательный сдвиг и сдвиг на 32+. Не подменять эти результаты стандартным поведением JavaScript без проверки.

Дополнительно сверить схемами в игре: `Each({red}) + Signal(железо,{green})`, отмену канала после суммирования выбранных цветов и случаи разного набора присутствующих сигналов на двух входах. Для каждого случая сохранить настройки, входы и выход после одного тика. Приведённые выше примеры и таблицы сами по себе не заменяют такую проверку.

## Дополнительная сверка чисел 16.11.2026

Официальный [API релизов](https://factorio.com/api/latest-releases) по-прежнему сообщает stable 2.1.24 (alpha/expansion). Повторно просмотрены Wiki и сообщения на форуме. [Wiki арифметического](https://wiki.factorio.com/Arithmetic_combinator) описывает операции, знаки деления/остатка и арифметический правый сдвиг. Исторический [отчёт об умножении](https://forums.factorio.com/51033) относится к 0.15.30; он подтверждает происхождение известного wraparound, но не заменяет эталон текущей stable. Отдельно не путать результат операции и ограничения числового поля GUI: это [разные случаи](https://forums.factorio.com/viewtopic.php?t=132526).

Точного актуального описания крайних степеней (переполнение, отрицательный показатель, 0^0) в найденных источниках нет. Поэтому не закреплять поведение `Math.pow`, `**` или BigInt как правило игры. Нужны эталоны Factorio 2.1.24: `MAX*MAX`, `MIN*(-1)`, `65537*65537`, `3^20`, `2^31`, `2^32`, `0^0`, `0^-1`, `2^-1`, `(-1)^MIN`, а также ранее перечисленные деление/остаток на 0 и границы сдвига. Сохранить входы, настройки и выход через тик, включая отсутствие нулевого канала.

`MAX*MAX=1`, `65537*65537=131073`, `3^20=-808182895` — контрольные ожидания **целочисленной проектной модели**, а не выполненные игровые проверки. Точные JS-примитивы описаны в [сетях](networks.md). BigInt-оракул проверяет реализацию модели; он не является независимым свидетельством поведения Factorio.

## Что выполняет симулятор

Имена `Arithmetic.Operation` сопоставлены игровым операциям: `SUM` `+`, `SUB` `-`, `MUL` `*`, `DIV` `/`, `MOD` `%`, `POW` `^`, `SHL` `<<`, `SHR` `>>`, `AND`, `OR`, `XOR`. Текст операции не исполняется как JavaScript: `POW` не является XOR.

Для поддержанных ветвей результат — знаковое int32. Умножение идёт через `Math.imul`. Деление отбрасывает дробную часть к нулю, остаток сохраняет знак делимого, правый сдвиг арифметический. Сдвиг на 0..31 оборачивает значение в int32. Степень с положительным показателем выполняется, только если точный результат помещается в int32; основания −1, 0 и 1 не строят промежуточное произведение.

`Each` допустим в одном операнде. Выход `Each` повторяет каналы этого входа, конкретный сигнал складывает результаты по int32. Обычный второй операнд — одно число: константа либо сигнал с той же маской. Нулевой итог в выход не пишется. `null`-операнд и невыбранный `return` дают пустой вклад и не вычисляют операцию.

Следующие ветви не подменяются моделью и дают `unsupported-case`. Конфигурация отклоняется до запуска, значение — при шаге; опубликованная граница при ошибке шага не меняется.

| Ветвь | Когда |
|---|---|
| Each и обычный сигнал с разными масками | конфигурация |
| Деление и остаток на ноль, `MIN / -1`, `MIN % -1` | вычисление |
| Показатель степени `< 0` или `0`, либо точный результат вне int32 | вычисление |
| Сдвиг `< 0` или `>= 32` | вычисление |
| Each по обоим цветам, если канал есть на красном и зелёном и их int32-сумма равна 0 | вычисление |

`Anything` и `Everything` дают `unsupported-mode`. Два `Each` и выход `Each` без операнда `Each` дают `invalid-each`. Обычное чтение одного сигнала, у которого красный и зелёный вклады погасили друг друга, остаётся 0: это правило сети, не режим `Each`.

`3^20=-808182895` и прочие обёрнутые степени в симулятор не подставлены. Игрового fixture для таблицы выше нет; статус этих ветвей — явная неподдержка, не совместимость с Factorio 2.1.24.
