# Лампа

Наблюдатель сети. В выбранный срез 19.11.2026 входит условие включения и три цветовых режима. Лампа не пишет сигналы. Запуск Factorio 2.1.24 не выполнялся.

Источники описания, сверенные 19.11.2026 при stable 2.1.24: [Wiki лампы](https://wiki.factorio.com/Lamp), строка лампы в [Wiki сетей](https://wiki.factorio.com/Circuit_network), [LampBlueprintControlBehavior](https://lua-api.factorio.com/2.1.24/concepts/LampBlueprintControlBehavior.html).

## Конфигурация

Обязательны `condition` и `use_colors`. Входы `red_input` и `green_input` можно пропустить: это `null`. `red_output` и `green_output` запрещены, в том числе явным `null`.

Условие — ровно один объект `{ left_operand, operation, right_operand }`. Несколько условий, `Each`, `Anything`, `Everything` и логистическое условие не входят в форму. `operation` — константа `Lamp.Operation`: `GT`, `LT`, `EQ`, `GTE`, `LTE`, `NEQ`. Левый операнд — обычный сигнал с маской `red` и `green`. Правый — такой же сигнал либо `{ constant: int32 }`. Пропущенный канал читается как 0. Значение API по умолчанию не подставляется.

`use_colors: false` запрещает `color_mode`. `use_colors: true` требует `mapping`, `components` или `packed`. Поле API `color_mode` по умолчанию равно mapping; эта модель его не подставляет.

Ключи `logistic_condition`, `connect_to_logistic_network`, `circuit_enabled`, `red_signal`, `green_signal`, `blue_signal` и `rgb_signal` дают `unsupported-case`. Другое неизвестное поле — `invalid-lamp-config`.

## Граница наблюдения

Лампа читает сети после того, как граница уже собрана из постоянных источников и комбинаторов. Состояние доступно как `simulation.device(lamp).state` и входит в снимок. Собственный выход пуст, поэтому агрегат сети от лампы не меняется.

Прямой постоянный сигнал виден на границе 0. Выход комбинатора виден на границе его публикации, без дополнительной задержки лампы. Это правило проекта: тактом лампы игра не проверялась.

Оптимизированный проход заново читает лампу только при изменении её входной сети.

## Цвет

Цвет считается только при истинном условии и `use_colors: true`. Иначе `color` равен `null`, даже если цветовые сигналы есть. Суммируются оба подключённых входа, а не маска операнда условия. Участвует только обычный виртуальный сигнал качества `normal`. Другое качество в выборе цвета не участвует; это не проверено игрой.

| Режим | Наблюдение |
|---|---|
| `mapping` | Первый сигнал с количеством больше 0 в порядке `signal-red`, `signal-green`, `signal-blue`, `signal-yellow`, `signal-pink`, `signal-cyan`, `signal-white`, `signal-grey`, `signal-black`. Нуль и отрицательное количество пропускаются. Если такого сигнала нет, `color` равен `null` |
| `components` | `{ red, green, blue }` из `signal-red`, `signal-green`, `signal-blue`. Каждое значение должно быть целым 0..255. Иначе `unsupported-case`, граница не публикуется |
| `packed` | Целое 0..16777215 на `signal-white`. Иначе `unsupported-case`. Байты цвета не разбираются |

Порядок mapping взят из сообщения форума 2.1.17 и ответа, что поведение схемы в 2.1.18 не менялось; Wiki обещает список, но извлечённый текст его не содержит. Большее число более позднего сигнала не обгоняет более ранний. Яркость серого и чёрного не моделируется: сохраняется только имя выбранного сигнала. Белый свет выключенного цветового режима не кодируется отдельным значением.

Пока условие ложно, диапазон компонентов и packed не проверяется.
