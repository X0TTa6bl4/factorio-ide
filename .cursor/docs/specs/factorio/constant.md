# Постоянный комбинатор

## Правила игры

Источник непрерывно выдаёт настроенные сигналы в подключённые выходные сети. Вход для вычисления не нужен; устройство включается и выключается вручную и не требует электричества. Для управления по сигналу его выход можно пропускать через сравнивающий. [Constant combinator](https://wiki.factorio.com/Constant_combinator).

Текущий API задаёт флаг `enabled` и список логистических секций. Секция содержит фильтры, группу, признак активности и множитель. Именованные группы позволяют переиспользовать наборы настроек. [Устройство](https://lua-api.factorio.com/latest/classes/LuaConstantCombinatorControlBehavior.html), [секция](https://lua-api.factorio.com/latest/classes/LuaLogisticSection.html).

При использовании логистического фильтра передаётся его минимальное значение; максимум запроса не становится выходным значением. [Пояснение Wiki](https://wiki.factorio.com/Constant_combinator).

## Проектная модель

Хранить отдельно общий флаг включения, секции и записи сигналов. Дублирующиеся каналы дают суммарный вклад по int32; нулевой итог удаляется. Выключенный источник не публикует ни одну секцию. Выключенная секция не публикует только свой вклад. Ключ канала — `type + name + quality`, по правилам [сетей](networks.md).

Форма задана в [API](../api.md). `signals` и `sections` взаимоисключающи. Массив `signals` равен одной активной секции без группы и с множителем 1: у фильтра `min` равен `constant`, `max` равен `null`.

Секция содержит `active`, `multiplier` и `group`. При `group: null` обязателен свой массив `filters`. Фильтр — `{signal, min, max}`. В сеть пишется `min`. `max` хранится и выходным значением не становится; `null` означает, что максимум не задан. Пустая секция и пустой список фильтров допустимы.

`multiplier` — конечное число, и поддержано только значение `1`. `0`, дробные, отрицательные и прочие конечные значения дают `unsupported-case`: округление и переполнение произведения этим типом не задаются, пока нет игрового fixture нужной stable. Нечисло, `NaN` и бесконечность дают `invalid-multiplier` и не приводятся молча. Сложение вкладов одного канала остаётся обычным int32: `2147483647 + 1` становится `-2147483648`, ` -2147483648 + -1` становится `2147483647`.

`Constant.Group` хранит непустую строку-метку и список фильтров. Идентичность группы — сам объект. Одинаковая метка не сливает разные объекты. Строка в `group` даёт `unsupported-case`: общий логистический каталог по имени игры не поддержан без fixture. Удаления группы нет. `replaceFilters` меняет список целиком; при ошибке нового списка прежний остаётся.

Вклад читается при создании прогона. Граница 0 и каждый следующий шаг этого прогона повторяют снятые количества и не накапливают их. `reset` возвращает границу 0 того же снимка. Изменение группы или `enabled` видно всем секциям этой группы на границе 0 следующего прогона. Это согласовано с [тиками](ticks.md): настройки уже идущего прогона не перечитываются.

Постороннее поле, неверный сигнал, неверная сеть и нечисловое количество дают диагностику с устойчивым `code`.

## Проверки

| Настройка | Ожидаемый вклад |
|---|---|
| Включённый источник `A=5` | `A=5` на каждой границе |
| Тот же источник после 10 шагов | Всё ещё 5, а не 50 |
| Общий `enabled=false` | Пустой выход |
| Две активные секции `A=2`, `A=3` | `A=5` |
| Секция с `A=3` выключена | Вклад только другой секции |
| Фильтр `min=5`, `max=10` | `A=5` |
| `A=2` и `A=-2` | Канала A нет |
| `2147483647` и `1` одного канала | `-2147483648` |
| Общая группа `A=2` у двух секций, затем фильтры группы `A=3` | Новый прогон публикует новое значение у каждой секции; прежний прогон сохраняет 2 |

Дробные и отрицательные множители, округление и переполнение произведения требуют fixture stable-игры. До него симулятор возвращает `unsupported-case`. Сложение int32 выше — проектная числовая модель сетей, не отдельное доказательство поведения множителя в игре.
