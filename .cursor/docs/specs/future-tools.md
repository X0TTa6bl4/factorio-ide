# Дополнительные средства

Решение задачи 0023 от 19.11.2026. Документ задаёт, какие средства после этапа 6 входят в объём, а какие остаются вне него. Реализация обзора и разбора — задачи 0024 и 0025; этот документ их не выполняет.

Игровая семантика устройств остаётся в `factorio/`. Файл схемы — в [документе схемы](project-document.md). Текст конфигурации — в [редакторе](editor.md).

## Критерий

Средство принимается, когда одновременно выполнены пять условий:

1. Текущие страницы не закрывают наблюдаемый сценарий.
2. Средство читает уже принятый документ `f-logic-project` и не вводит вторую семантику тика.
3. Ошибочный вход даёт код диагностики и не подменяет последнюю успешную схему.
4. Совместимость с игрой не выводится из формы API и не заявляется без игрового прогона.
5. Достаточно HTML, CSS и обычного JavaScript. Новая обязательная библиотека, сборщик и холст-редактор не требуются.

## Что уже есть

| Страница | Что пользователь видит |
|---|---|
| `pages/configure/index.html` | Текст деклараций и порты по именам `red_*` / `green_*` |
| `pages/networks/index.html` | Имена сетей, создание и переименование |
| `pages/debugger/index.html` | Порты одного устройства и агрегат одной сети после шага |
| `pages/project/index.html` | Файл версии 1, атомарный импорт |

Демонстрации отладчика содержат несколько устройств. Тот же текст конфигурации уже выражает общую сеть и петлю, но ни одна страница не показывает всю схему целиком: кто пишет в сеть, кто её читает и замыкается ли путь.

## Решение по инструментам

| Инструмент | Наблюдаемый сценарий | Рассмотренный другой объём | Решение |
|---|---|---|---|
| Визуальные провода | Понять связи сложной схемы, уже записанной текстом или файлом | Редактор, в котором устройства перетаскиваются, а координаты хранятся в файле | Обзор только для чтения, задача 0025. Редактор холста вне объёма |
| Импорт blueprint | Открыть строку чертежа Factorio как схему | Частичный импорт с пропуском лишних сущностей | Вне объёма. Текущий импорт такой вход отклоняет |
| Экспорт blueprint | Получить строку, которую игра вставляет как чертёж | Считать кодировщик каталога сигналов готовым экспортом приложения | Вне объёма |
| Анализ | До шага узнать состав сетей и есть ли цикл обратной связи | Оценка задержки в игре, советы по переписыванию схемы, разбор текста `main` | Статический отчёт по портам, задача 0024 |

Редактор холста вне объёма: координаты не участвуют в тике, а текст конфигурации и файл версии 1 уже задают те же порты. Второй редактор разошёлся бы с этой моделью.

Экспорт чертежа вне объёма: у документа нет положения, направления и игрового `control_behavior`. Сгенерированная строка выглядела бы как чертёж, не будучи сверенной с игрой. `tools/signal-catalog/survey-blueprint.mjs` кодирует обзор каталога для сверки сигналов и не является экспортом приложения.

Потерянный или неподдержанный фрагмент чертежа не считается принятым молча. Пока импорта чертежа нет, такой фрагмент в схему не попадает. Если отдельное поручение позже закажет импорт, он применяется только целиком: неподдержанная сущность, провод или поле настройки отвергают весь чертёж, перечисляют причину и оставляют открытую схему прежней. Это условие будущего поручения, а не задача реализации.

В JSON каталога `data/` ключ `wires` отсутствует: сохранённые чертежи — постоянные комбинаторы с секциями фильтров, без проводов между устройствами. ## Отчёт структуры

Модуль `src/circuit-structure.js` экспортирует `circuitStructure(document)`. Вход — объект документа версии 1. Функция проводит его через `readProject`. Ошибка загрузчика пробрасывается с тем же `code`; отчёт при этом не возвращается. `step` и `reset` не вызываются. Текст `source` события не читается: учитываются только порты.

Отчёт — структурная принадлежность портов. Он не содержит значений сигналов и не подтверждает задержку. Правило одного тика арифметического, сравнивающего и выбирающего остаётся в [тиках](factorio/ticks.md); этот отчёт его не пересчитывает и игрой не подтверждает.

```js
{
  networks: [
    {
      id, name, color,
      readers: [{ id, name, kind, port }],
      writers: [{ id, name, kind, port }]
    }
  ],
  feedback: [
    { color, cyclic, self: [{ networkId, deviceIds }], witness }
  ]
}
```

`networks` перечисляет все сети документа, включая сети без портов. Порядок — по целому номеру в id вида `nN`. Читатели и писатели упорядочены по целому номеру id устройства, затем по порту. Читатель — устройство с `red_input` или `green_input`, указывающим на эту сеть. Писатель — устройство с `red_output` или `green_output` на эту сеть. Лампа не становится писателем: выходные порты ей запрещены. У поезда портов нет, поэтому в списках его нет. Хранилище и станция попадают в писатели, если выход подключён; это факт порта, а не утверждение о каждом тике. Событие попадает в список по подключённым портам.

`feedback` содержит цвет `red`, затем `green`, только если у этого цвета есть хотя бы один читатель или писатель. `self` — сети этого цвета, у которых один и тот же id устройства есть и среди читателей, и среди писателей. Сети упорядочены по номеру id, `deviceIds` — по номеру id.

Граф цвета: вершина — устройство, которое читает или пишет сеть этого цвета. Ребро `u → v`, в том числе петля `u → v` при `u === v`, проводится, когда какая-либо сеть этого цвета имеет `u` среди писателей и `v` среди читателей. Соседи упорядочены по номеру id. `cyclic` истинен, когда в графе есть ориентированный цикл, включая петлю.

`witness` равен `null`, пока цикла нет. Иначе это один замкнутый обход, а не список всех циклов:

1. Вершины обходятся в порядке номера id. Поиск в глубину красит вершину серым при входе и чёрным при выходе.
2. Первый сосед, который уже серый, замыкает цикл: срез стека от этой вершины до вершины стека и повтор серой вершины в конце.
3. Тело без повторённого конца вращается влево, пока на первом месте не окажется наименьший номер id. То же делается с обратным телом. Из двух последовательностей берётся лексикографически меньшая по номерам id, затем в конец дописывается её первый id.

Для единственной петли устройства `d3` свидетель — `["d3", "d3"]`. Для рёбер `d1 → d2` и `d2 → d1` свидетель — `["d1", "d2", "d1"]`.

## Страница обзора

Страница `pages/structure/index.html` показывает отчёт одной схемы. Поле принимает JSON документа версии 1. Пустое поле оставляет пустое состояние «Схема не загружена» и не рисует сети.

Успешный разбор заменяет обзор: сети, читатели, писатели, `cyclic`, прямые петли и свидетель идут в порядке отчёта. Ошибка показывает `code` и сохраняет предыдущий успешный обзор. Если успешного обзора ещё не было, остаётся пустое состояние и код. Координаты не записываются, перетаскивания нет, файл схемы новыми полями не расширяется. Страница не вызывает `step`.

Проверка страницы смотрит имена, цвет, порядок и код ошибки. Совпадение пикселей раскладки критерием не является.
