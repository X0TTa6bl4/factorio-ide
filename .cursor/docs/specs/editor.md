# Правила редактора конфигурации

Документ задаёт подсказки, диагностику и порядок проверки. Формы объектов и значения по умолчанию определяются в [объектном API](api.md), игровая семантика — в `factorio/`. Реализации редактора пока нет.

## Источники проверок

| Что проверяется | Основной документ |
|---|---|
| Поля, операнды, константы, подключения и выходные ветки | [Объектный API](api.md) |
| Цвет, идентичность и принадлежность сети; числовая модель | [Сети и сигналы](factorio/networks.md) |
| Операции и допустимость Each в арифметическом | [Арифметический](factorio/arithmetic.md) |
| Условия, режимы количества и допустимые выходы сравнивающего | [Сравнивающий](factorio/decider.md) |
| Русские названия и ID метасигналов | [Метасигналы](factorio/meta-signals.md) |
| Доступность прототипов и игровых возможностей | [Каталоги](factorio/catalog.md), [совместимость](compatibility.md) |

При изменении правила обновлять основной документ и зависимые примеры диагностики. Не поддерживать в редакторе вторую, расходящуюся таблицу игровой семантики.

## Порядок проверки

1. Проверить синтаксис JavaScript и имена свойств.
2. Проверить тип каждого поля, обязательные поля выбранного варианта и отсутствие посторонних полей. Вложенные объекты проверяются так же строго, как конфигурация целиком.
3. Проверить значения: принадлежность констант своему типу, конечность и целочисленность чисел, диапазон int32, цвет и принадлежность сети схеме.
4. Проверить совместимость настроек всего комбинатора. В сравнивающем учитывать весь массив условий и каждую настройку обеих выходных веток.

Общий тип объекта не разрешает все константы во всех позициях. Подсказки зависят от комбинатора, поля и остальных настроек. Например, доступность выходного «каждый» зависит от условий, а не только от наличия `$EACH` в каталоге.

## Подсказки и диагностика

- Предлагать только допустимые значения. Запрещённое сочетание скрывать из допустимых подсказок и диагностировать, если оно уже введено или вставлено.
- Использовать названия из справочника метасигналов; не предлагать «каждый» и «все» как синонимы.
- Подсвечивать конкретное свойство или значение, указывать ожидаемый тип и причину ошибки. Для ошибки сочетания показывать связанные поля.
- Не исправлять смысл молча: не преобразовывать строки в числа, не округлять константы и не заменять метасигналы.
- `null` у операнда означает «не задан». В сравнении такое условие всегда ложно и участвует в AND/OR как `false`. Маска `false/false` допустима: она выбирает пустой вход, где обычный сигнал читается как 0 и в арифметическом, и в сравнивающем; для метасигналов действуют правила пустого набора. Не смешивать эти случаи.
- Для подключений предлагать ссылки на уже созданные редактором/движком сети текущей схемы подходящего цвета. Для сигналов разворачивать дерево `Signal`, в том числе `Signal.Logistic.$WOOD_BOX`; перечень констант брать из выбранного профиля данных.
- Не объявлять игровые случаи проверенными на основании корректных типов. Неподдержанный режим должен иметь явную диагностику.

## Проверка перед запуском и после импорта

Проверка обязательна в конструкторе/при подготовке схемы к запуску и после импорта. Подсветка редактора не заменяет её. Ошибочная конфигурация не передаётся движку.

Класс JavaScript сам по себе не обеспечивает статическую типизацию. Описание типов, проверка редактором и валидация при выполнении — разные обязанности. Инструмент типизации и библиотека редактора ещё не выбраны; переход на TypeScript и установка зависимостей не согласованы.

## Контрольные случаи будущей реализации

| Пример | Ожидаемая диагностика |
|---|---|
| `red_input: red_10` | Допустимо при ссылке на красную сеть текущей схемы |
| Подключение не записано | Допустимо; значение порта `null` |
| `red_input: "red_10"` | Требуется ссылка на сеть или `null`, получена строка |
| `red_input: Arithmetic.Operation.SUM` | Операция не является сетью |
| `red_input: green_100` | Цвет сети не соответствует порту |
| `{ red: true, green: false, signal: $IRON }` | Допустимый `Operand` |
| `{ red: 1, green: false, signal: $IRON }` | `red` должен быть boolean |
| `{ red: true, signal: $IRON }` | Отсутствует обязательное поле `green` |
| `{ red: true, green: false, signal: Arithmetic.Operation.SUM }` | Операция не является сигналом |
| `{ constant: 5 }` | Допустимый `OperandConst` |
| `{ constant: 5, signal: $IRON }` | Смешаны два взаимоисключающих типа операнда |
| `{ constant: 5, red: false }` | Цветовой флаг не допускается у `OperandConst` |
| `{ constant: "5" }` | Требуется число |
| `{ constant: 1.5 }` | Требуется целое число |
| `{ constant: 2147483648 }` | Значение вне диапазона int32 |
| `right_operand: 0` | Требуется `Operand`, `OperandConst` либо `null` |
| `right_operand: null` | Допустимый незаданный операнд; не числовой 0 |
| `{ red: false, green: false, signal: $IRON }` | Допустимо; в сравнении обычный канал пустого входа читается как 0 |
| Фиксированный выход `Signal.Meta.$EVERYTHING` с `constant` и полной маской | Допустимая форма; отдельно проверить совместимость с условиями |
| Арифметический `return: 123` | Требуется константа выходного сигнала/метасигнала |
| Оба операнда арифметического используют `$EACH` | Недопустимое сочетание настроек |
| Арифметический выход `$EACH` без операнда `$EACH` | Недопустимое сочетание настроек |
| Сравнивающий выход `$EACH` без `$EACH` в условиях | Недопустимое сочетание настроек |
| Сравнивающий выход `$EVERYTHING` при `$EACH` в условиях | Недопустимое сочетание настроек |

Это примеры диагностики по основным спецификациям, а не дополнительные определения типов и не отчёт о пройденных тестах приложения.


Открытые вопросы формы данных собраны в [API](api.md); вопросы поведения игры — рядом с семантикой соответствующего комбинатора.
