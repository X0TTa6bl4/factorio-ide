# Runtime-сверка 18.11.2026

Реально запущена официальная headless Factorio **2.1.24, build 87808, linux64** в Docker linux/amd64. SHA-256 архива совпал с исходным снимком: `c49b66cff90aceff87b30f2973af0df7f51712cb2ee3153e0169d9bed46a964f`. [Воспроизведение](../../../tools/factorio-catalog/runtime-probe/README.md), источник архива — [Wube](https://factorio.com/get-download/2.1.24/headless/linux64).

## Область

- `base.json`: 1218 строк; активны base 2.1.24 и диагностический `f-logic-catalog-probe` 0.1.0.
- `space-age.json`: 2249 строк; активны base, elevated-rails, quality, recycler, space-age 2.1.24 и тот же probe.
- Мод только читает runtime на создании временной карты, не меняет data stage. Точные `activeMods` сохранены в каждом JSON.
- Все восемь множеств type/name совпадают с соответствующим сырым снимком; группировка и некоторые defaults получены движком после data stage.
- `status: present` означает успешное чтение; `absent` — nil; `unsupported` — это поле не читается у данного объекта. nil не превращён в false.

## Подтверждённые результаты

Для каждого из четырёх `asteroid-chunk` — metallic, carbonic, oxide, promethium — движок вернул `hide_from_signal_gui = true`, а `item_signal_alias.name` совпал с именем соответствующего предмета. Технический вопрос видимости/alias закрыт. Это отдельное runtime-свидетельство: в старом сыром data-stage JSON этих полей по-прежнему нет. Предметные публичные пути менять не требуется.

Для всех обычных рецептов обоих профилей проверено `hide_from_signal_gui`. Найдено одно расхождение первоначального генератора: `recipe/rocket-part` имеет **false**, хотя эвристика совпадения иконки со скрытым `item/rocket-part` давала hidden. Исправлено участие скрытых item/fluid/virtual в индексе сравнения иконок; регрессия проверяет и fixture, и реальные runtime-строки.

В исходном снимке у recipe/rocket-part также нет subgroup/order. Добавлено наследование отсутствующих полей рецепта от единственного/главного продукта с сохранением явных настроек и указанием происхождения. Все унаследованные значения обоих профилей сверены с runtime: для base — 176 subgroup и 178 order, для Space Age — 246 subgroup и 349 order, расхождений нет. В результате появился ранее пропущенный путь `Signal.Intermediate.rocket_part` в base и `Signal.Space.rocket_part` в Space Age. Число экспортов — 570/877; исходные 1218/2249 строк сохранены. Это исправление вычисленной классификации и метаданных, а не подтверждение всего графического меню.

`entity/demolisher-ash-sticker` в Space Age имеет runtime hidden=true при hidden=false в сыром снимке. Остальные hidden и все parameter совпадают. Эта запись и раньше не экспортировалась как обычный публичный сигнал, но разница defaults должна быть сохранена при последующем подключении runtime-метаданных.

В Space Age среди 264 нескрытых environment-сущностей 186 имеют `selectable_in_game = false`, 78 — true. Это **не** правило фильтрации chooser: у `entity/cliff` selectable_in_game=false, хотя утёсы видны в пользовательском меню. У `entity/lightning-rod-remnants` значение true само по себе также не доказывает кнопку сигнала. Массовое удаление всех невыбираемых на карте сущностей из публичной таблицы запрещено без проверки меню.

## Что не проверено этим запуском

Графическое меню и его полный состав; картинки; перевод через подключённого клиента; все качества и ограничения их выбора. Поэтому `menuConfirmed` остаётся false. Результаты относятся только к указанной версии и профилям, не являются автоматическим подтверждением latest или любых модов.
