# Инструкции для f logic

## Проект и принятые границы

Это будущий лёгкий браузерный инструмент проектирования и пошаговой симуляции логических сетей Factorio по мотивам cnide. На первом этапе — арифметический, сравнивающий, постоянный и выбирающий комбинаторы; остальные устройства и поезда позднее. Объектный JavaScript API и UI должны работать с общей моделью схемы; отдельный псевдоязык заменён конфигурацией классов.

Согласованы HTML, CSS, JavaScript и нативные ES-модули, запуск по ссылке в браузере. Обсуждение стека и настройка агентов не являются поручением создать приложение. TypeScript, сборщик и библиотеки не входят в согласованный стек. Запуска по ссылке достаточно; открытие двойным кликом по локальному HTML не требуется. Не считать обсуждение стека поручением на реализацию или развёртывание.

## Структура агента

- `.cursor/skills/` — единственный набор локальных скиллов.
- `.agents` — относительная ссылка на `.cursor`, чтобы Codex видел тот же набор.
- `.cursor/rules/` — правила Cursor; основные общие нормы описаны здесь.
- `.cursor/docs/` — документация агента; `.cursor/tasks/` — явно создаваемые задачи.
- Навигация: `.cursor/skills/repo-orientation-ru/SKILL.md`; карта workflow: `skills.md` рядом с ним.

Не читать все скиллы заранее. Открывать подходящий `SKILL.md` и только нужные связанные материалы. После установки скиллы могут потребовать следующего хода для автоматического обнаружения.

## Работа

Отвечать по-русски; идентификаторы сохранять как в коде. Перед правкой читать применимые инструкции и конфигурацию проекта. Искать через `rg`, ограничивать обход текущим проектом, не включать зависимости и результаты сборки без причины.

Использовать фактический Git-корень; здесь `.cursor` не отдельный Git-репозиторий. Сохранять чужие изменения. Коммит, публикация и внешние записи выполняются в рамках поручения пользователя. Не переносить MCP credentials, `.env`, токены, историю чатов и дампы из других workspace.

Тесты и сборку выбирать по реальному стеку и риску изменения. По требованию пользователя устанавливаемые инструменты разработки и тестирования запускать через Docker; подготовка окружения — первая задача реализации. Конечному пользователю достаточно браузера. Не требовать PHP 7.3, Laravel, Jira, Spec Kit и корпоративные сервисы `kmut-ml`. Для движка и комбинаторов требуется максимальное покрытие тестами. Не навязывать конкретные модели агентов, отдельные чаты и субагентов. Делегирование — только когда разрешено пользователем или другими применимыми инструкциями.

Движок симуляции держать независимым от DOM и таймера отрисовки; различать описание схемы и состояние выполнения. Игровую семантику проверять для согласованной версии Factorio. Не вводить слои и зависимости без задачи на них.

Результат проверки сообщать по фактическому прогону; незапущенное не называть успешным. Задачи и документацию создавать по необходимости, не для каждой простой правки.
